[ MISSION 01 ] // CREATE RESOURCE GROUP

OBJECTIVE: Skapa en container för labbens Azure-resurser.

SUBSCRIPTION │ ▼ RESOURCE GROUP │ ├── VM ├── Network ├── Public IP └── Disk
  1. Logga in i Azure Portal.
  2. Kontrollera att du använder rätt subscription.
  3. Sök efter Resource groups.
  4. Skapa en ny Resource Group.

Använd exempelvis:

rg-cloudlab-student01

Välj en region som är tillgänglig för din student-subscription.

QUESTION:

Varför är det praktiskt att lägga labbens resurser i samma Resource Group?

Resurserna blir enklare att organisera och du kan senare ta bort hela Resource Group för att städa bort labbmiljön.
[ MISSION 02 ] // DEPLOY LINUX VM

OBJECTIVE: Skapa en liten Linux-baserad virtuell maskin.

Skapa en ny Virtual Machine i Resource Group från Mission 01.

Exempel:

VM NAME: web01 OPERATING SYSTEM: Ubuntu Linux AUTHENTICATION: SSH public key SIZE: Choose a small / inexpensive size available for your subscription.
TILLGÄNGLIGA VM-STORLEKAR OCH PRISER KAN VARIERA MELLAN REGIONER OCH SUBSCRIPTIONS. KONTROLLERA DEN VISade KOSTNADEN INNAN DU SKAPAR VM:N.

När VM:n skapas kommer du upptäcka att Azure behöver fler resurser än bara själva VM:n.

Virtual Machine │ ├── Network Interface │ ├── Virtual Network │ ├── Public IP │ └── OS Disk
QUESTION:

Är en virtuell maskin i Azure bara en enda isolerad resurs?

Nej. En fungerande VM använder flera Azure-resurser, exempelvis nätverk, nätverksinterface, disk och eventuellt en publik IP-adress.
[ MISSION 03 ] // CONNECT

OBJECTIVE: Anslut till din VM via SSH.

Hitta VM:ns publika IP-adress.

VM └── Overview └── Public IP address

Anslut från din dator:

ssh USERNAME@PUBLIC_IP

Exempel:

ssh azureuser@20.x.x.x
Du ska nu ha ett shell på din Linux-server i Azure.

Kontrollera vilken maskin du är på:

hostname whoami ip addr
THINK:

Servern finns i Microsofts datacenter. Vem administrerar operativsystemet inne i denna IaaS-VM?

CUSTOMER. I en IaaS-modell hanterar kunden normalt operativsystemet i sin virtuella maskin.
[ MISSION 04 ] // INSTALL WEB SERVER

OBJECTIVE: Installera nginx på VM:n.

sudo apt update sudo apt install nginx -y

Kontrollera status:

systemctl status nginx

Du kan också testa lokalt på servern:

curl http://localhost
Om du får HTML tillbaka kör nginx.

Testa nu från din egen webbläsare:

http://PUBLIC_IP
QUESTION:

Fungerar webbsidan från Internet?

Om inte — fundera på vilka nätverksregler som styr trafiken till VM:n.

[ MISSION 05 ] // OPEN TCP/80

OBJECTIVE: Tillåt HTTP-trafik till webbservern.

Undersök VM:ns nätverksinställningar och Network Security Group.

Skapa eller kontrollera att det finns en inbound-regel som tillåter:

PROTOCOL: TCP DESTINATION PORT: 80 ACTION: ALLOW
INTERNET │ │ TCP/80 ▼ Public IP │ ▼ Network Security Group │ ▼ Network Interface │ ▼ Linux VM │ ▼ nginx

Testa igen:

http://PUBLIC_IP
Du bör nu kunna nå nginx från din webbläsare.
