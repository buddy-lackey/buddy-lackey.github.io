NETWORK SECURITY / PHYSICAL SWITCH LAB

BLOCK THE PING

FortiSwitch · Standalone · Access Control Lists. En praktisk övning där ni först verifierar kommunikationen mellan två Windows-datorer och sedan blockerar ICMP med en ACL på switchen.

SWITCH SECURITY LAB ONLINE_

// MISSION

Mål: PC1 ska kunna pinga PC2 innan ACL:en aktiveras. När ni applicerar en ingress ACL på porten där PC1 är ansluten ska ICMP Echo Request från PC1 till PC2 blockeras. Efter att ACL:en tas bort ska ping fungera igen.

Arbeta endast på de portar och den FortiSwitch som läraren har anvisat. Ändra inte managementport, uplink eller portar som andra grupper använder.

PC1
192.168.10.10/24
Windows
── Port 1 ──
FortiSwitch
Standalone
VLAN 10
── Port 2 ──
PC2
192.168.10.20/24
Windows
Viktigt: PC1 och PC2 ligger i samma IP-subnät och VLAN. Trafiken behöver inte routas. Syftet är att undersöka om switchens ACL-funktion kan filtrera ICMP på ingressporten även när trafiken switchas på lager 2. Stödet måste verifieras för er modell och firmware.

// CHALLENGES

CHALLENGE 01 / BUILD

Connect the hosts

  1. Anslut PC1 och PC2 till var sin anvisad switchport.
  2. Kontrollera att båda portarna tillhör samma VLAN.
  3. Konfigurera IP-adresser enligt topologin. Nätmask: 255.255.255.0.
  4. Kontrollera adresserna med ipconfig.
PC1: 192.168.10.10 / 255.255.255.0
PC2: 192.168.10.20 / 255.255.255.0

Behöver datorerna en default gateway för att kommunicera med varandra?

Reveal discussion

Nej. De ligger i samma subnät. PC1 kan använda ARP för att hitta PC2:s MAC-adress och därefter skicka Ethernetramar direkt via switchen.

CHALLENGE 02 / PREPARE WINDOWS

Allow ICMP in Windows Firewall

Windows Defender-brandväggen kan blockera inkommande ping även när nätverket fungerar. För att testet ska bli meningsfullt behöver PC2 tillåta inkommande ICMPv4 Echo Request.

  1. Öppna Start och sök efter Windows Defender-brandväggen med avancerad säkerhet, eller kör wf.msc.
  2. Välj Regler för inkommande trafik (Inbound Rules).
  3. Leta efter en regel med namnet File and Printer Sharing (Echo Request - ICMPv4-In) eller motsvarande svensk benämning.
  4. Aktivera rätt regel för den nätverksprofil som används. Om regeln saknas, skapa en ny inkommande anpassad regel som tillåter ICMPv4, typ 8 (Echo Request).
  5. Begränsa gärna regeln till den andra datorns IP-adress, och låt endast regeln vara aktiv under labben.
Stäng inte av hela Windows-brandväggen. En avgränsad regel för ICMP Echo Request är tillräcklig. Windows kan ha flera liknande regler för olika nätverksprofiler.

Varför behöver vi kontrollera Windows-brandväggen innan vi skapar en ACL på switchen?

Reveal discussion

Om PC2 blockerar ICMP redan från början kan vi inte avgöra om switchens ACL faktiskt orsakar blockeringen. Vi behöver först ett fungerande utgångsläge.

CHALLENGE 03 / BASELINE

Verify communication

Kör från PC1:

ping 192.168.10.20
arp -a

Dokumentera om ping fungerar och vilken MAC-adress som hittas för PC2. Testa även från PC2 till PC1, men kom ihåg att PC1 då också behöver tillåta inkommande Echo Request.

Om ping misslyckas redan nu: vilka tre saker kontrollerar ni först?

Reveal discussion

Kontrollera IP-adresser och nätmask, att switchportarna ligger i samma VLAN och att Windows-brandväggen tillåter inkommande ICMP Echo Request på mottagaren. Kontrollera även länkstatus.

CHALLENGE 04 / INVESTIGATE

Find the ACL feature

Identifiera FortiSwitch-modell, firmwareversion och hur ACL:er hanteras i standalone-läge. Använd switchens hjälp, GUI eller dokumentation för just er modell.

Ta reda på om den kan matcha:

  • Käll-IP: 192.168.10.10
  • Destinations-IP: 192.168.10.20
  • Protokoll: ICMP (IPv4)
  • Ingressport: porten där PC1 är ansluten

Kan modellen tillämpa en ACL på trafik som switchas mellan två portar i samma VLAN?

Reveal discussion

Detta måste verifieras för modellen och FortiSwitchOS-versionen. Anta inte att Cisco IOS-kommandon fungerar eller att alla FortiSwitch-modeller har samma ACL-kapacitet.

Om stödet saknas: dokumentera begränsningen i stället för att ändra topologin på egen hand.

CHALLENGE 05 / FILTER

Block ICMP from PC1

Skapa en ACL som nekar ICMP från PC1 till PC2 men tillåter övrig relevant trafik. Applicera ACL:en inbound/ingress på porten där PC1 är ansluten, om er modell stöder det. 

ÖNSKAD LOGIK (inte FortiSwitch CLI):

1. DENY   ICMP  192.168.10.10 -> 192.168.10.20
2. PERMIT övrig trafik

APPLICERING: ingress på PC1:s switchport

Varför är en uttrycklig tillåt-regel för övrig trafik viktig?

Reveal discussion

För att undvika att oavsiktligt blockera annan trafik. Den exakta hanteringen av omatchad trafik beror på ACL-typen och plattformen; kontrollera standardbeteendet i FortiSwitch-dokumentationen.

Använd inte Cisco-syntax som facit.

CHALLENGE 06 / VERIFY

Did the switch block it?

Testa från PC1:

ping 192.168.10.20
arp -a

Kontrollera därefter om annan trafik fortfarande fungerar, exempelvis en av läraren anvisad TCP-tjänst mellan datorerna. Kontrollera ACL-räknare eller statistik om switchen stöder det.

BEFORE ACL

PC1 → PC2: ICMP ska fungera.

AFTER ACL

PC1 → PC2: ICMP ska blockeras om ACL:en fungerar.

Kan PC2 fortfarande pinga PC1? Vad avgör svaret?

Reveal discussion

Det går inte att dra slutsatsen att PC2 → PC1 fungerar bara för att ACL:en sitter på PC1:s ingressport.

PC2:s Echo Request kan nå PC1, men PC1:s Echo Reply går sedan in genom samma filtrerade port. Om ACL:en nekar all ICMP från PC1 till PC2 blockeras även svaret.

Windows-brandväggen kan också påverka testet.

CHALLENGE 07 / RESTORE

Remove and retest

  1. Ta bort ACL:en från den aktuella switchporten.
  2. Verifiera att ping från PC1 till PC2 fungerar igen.
  3. Återställ tillfälliga Windows-brandväggsregler enligt lärarens instruktioner.
  4. Dokumentera vad som fungerade, vad som blockerades och hur ni verifierade orsaken.
Reveal discussion

Ett bra test har tre lägen: fungerande trafik före ändring, blockerad trafik efter ändring och återställd trafik efter rollback. Då blir det lättare att visa orsakssambandet.

  • ACL-konfiguration eller skärmbilder från GUI.
  • Resultat före ACL, med ACL och efter återställning.
  • En förklaring av vad ingress betyder i detta test.
