SIMULERA INTERNET_

● PACKET TRACER / NAT / ROUTING ONLINE

Du ska bygga tre varianter av ett simulerat Internet och undersöka vad som faktiskt krävs för att klienten ska kunna nå en extern destination. Börja enkelt med loopback, fortsätt med en riktig server och bygg slutligen ett nät med flera routrar.

// UPPDRAGET

Din roll: Du är nätverkstekniker. Ett internt LAN ska kunna kommunicera med externa resurser utan anslutning till det riktiga Internet. Använd Cisco Packet Tracer.

SCENARIO A / GRUND

Loopback på ISP-router

Simulera en extern IP-adress som kan svara på ping.

SCENARIO B / FORTSÄTTNING

Extern HTTP/FTP-server

Testa verkliga TCP-tjänster och observera PAT.

SCENARIO C / UTMANING

Flera routrar

Lägg till ett transitnät och felsök routing.

Viktigt: Adresserna 203.0.113.0/24 och 198.51.100.0/24 är dokumentationsnät. Här används de endast i den simulerade miljön. Loopback-adressen 8.8.8.8 i scenario A är också enbart simulerad.

CHALLENGE 01 — Bygg grunden

Reveal discussion / Cisco IOS-lathund

Exempel på NAT-routern (förutsätter att gränssnitten finns):

interface g0/0
 ip address 192.168.1.1 255.255.255.0
 ip nat inside
 no shutdown
interface g0/1
 ip address 203.0.113.1 255.255.255.0
 ip nat outside
 no shutdown
access-list 1 permit 192.168.1.0 0.0.0.255
ip nat inside source list 1 interface g0/1 overload
ip route 0.0.0.0 0.0.0.0 203.0.113.2

På ISP-routern: konfigurera 203.0.113.2/24 på gränssnittet mot NAT-routern och aktivera det. ACL 1 väljer adresser som ska NAT-översättas; den är inte i detta exempel en interface-applicerad filtreringsregel.

// SCENARIO A — LOOPBACK

PC ── L2 ── NAT ── ISP └── Loopback0: 8.8.8.8/32

CHALLENGE 02 — Ett Internet utan server

  1. Skapa Loopback0 på ISP-routern med IP-adressen 8.8.8.8/32.
  2. Pinga 8.8.8.8 från PC:n.
  3. Visa NAT-översättningar på NAT-routern.
  4. Förklara varför ISP-routern kan svara trots att ingen server finns.
interface loopback0
 ip address 8.8.8.8 255.255.255.255

Fundera: Kan du öppna http://8.8.8.8 i Packet Tracer och förvänta dig en webbsida? Varför/varför inte?

Reveal discussion

Loopback är ett virtuellt interface som tillhör ISP-routern. Den kan besvara ICMP echo requests till sin adress men erbjuder inte automatiskt HTTP eller FTP. Med PAT blir returtrafikens destination NAT-routerns outside-adress 203.0.113.1, som ISP-routern når direkt. På NAT-routern kan ICMP-översättningar synas i show ip nat translations under pågående trafik.

// SCENARIO B — EXTERN SERVER

192.168.1.100 ── L2 ── NAT ── ISP ── 198.51.100.10 198.51.100.1/24 HTTP / FTP

CHALLENGE 03 — Internet med riktiga tjänster

  1. Behåll grundtopologin. Lägg till en server bakom ISP-routern.
  2. Ge ISP-routerns andra interface 198.51.100.1/24.
  3. Ge servern 198.51.100.10/24 och gateway 198.51.100.1.
  4. Aktivera HTTP på servern (Services → HTTP). Aktivera FTP om du vill testa det också.
  5. Från PC:n: pinga servern, öppna http://198.51.100.10 och undersök NAT-tabellen.

Fundera: Vad skiljer en ICMP-översättning från en TCP-översättning? Varför kan en enda publik IP-adress användas för flera TCP-anslutningar?

Reveal discussion

HTTP ger TCP-trafik mot destinationsport 80. PAT kan översätta käll-IP och vid behov källport, så att flera anslutningar kan dela outside-adressen. ICMP använder inte TCP/UDP-portar; NAT-implementationer kan i stället använda ICMP-identifierare för att hålla isär flöden. ISP-routern har båda näten direktanslutna och behöver ingen extra statisk route för den här PAT-trafiken.

CHALLENGE 04 — Routing över flera hopp

  1. Utgå från grundtopologin, men använd adresserna ovan för de två nya näten.
  2. Konfigurera Internet-routern och servern.
  3. På ISP-routern: skapa en statisk route till 192.0.2.0/24 via 198.51.100.2.
  4. På Internet-routern: skapa en route tillbaka till 203.0.113.0/24 via 198.51.100.1.
  5. Testa ping, HTTP och tracert från PC:n. Jämför med scenario B.
Reveal discussion 
! ISP-router
ip route 192.0.2.0 255.255.255.0 198.51.100.2

! Internet-router
ip route 203.0.113.0 255.255.255.0 198.51.100.1

Returvägen behöver nå den NAT-översatta adressen 203.0.113.1, inte klientens privata adress. Traceroute kan visa flera hopp, men NAT och ICMP-beteende kan påverka vad som syns.

// VERIFIERA OCH FELSÖK

På PC:n

ipconfig
ping 192.168.1.1
ping 203.0.113.2
ping 8.8.8.8
tracert 192.0.2.10

På Cisco-routern

show ip interface brief
show ip route
show ip nat translations
show ip nat statistics
show access-lists

Använd bara tester som hör till det scenario du byggt. Generera trafik samtidigt som du tittar i NAT-tabellen, eftersom poster kan försvinna när de löper ut.

CHALLENGE 05 — Förklara dina resultat

  1. Vilka funktioner kan testas med loopback, men inte med en riktig tjänst?
  2. Vad måste finnas för att HTTP ska fungera i scenario B?
  3. Varför behöver Internet-routern i scenario C en returroute?
  4. Vilken IP-adress ser den externa servern som källa när PAT fungerar?
  5. Vad händer om du tar bort NAT-routerns default route?
Reveal discussion

A: Loopback ger IP-nåbarhet och ICMP-svar men inte automatiskt applikationstjänster. B: IP-konfiguration, fungerande routing/NAT och aktiv HTTP-tjänst. C: Serverns svar till 203.0.113.1 måste kunna routas tillbaka via ISP. Den externa servern ser normalt 203.0.113.1 som käll-IP. Utan default route saknar NAT-routern väg till de externa näten, om ingen annan passande route finns.
