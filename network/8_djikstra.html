// THE PERSON BEHIND THE ALGORITHM

Edsger W. Dijkstra (1930–2002)

Edsger Wybe Dijkstra was a Dutch computer scientist and mathematician. In 1956, he devised an elegant method for finding shortest paths through a network. The algorithm was published in 1959.

His original problem was inspired by finding the shortest route between two cities. The solution later became fundamental to computer science, navigation systems, and IP routing.

Dijkstra's algorithm finds shortest paths from one starting node to all reachable nodes in a graph with non-negative edge weights.

In networking, those weights can represent link costs rather than geographical distance.

Fun fact: Dijkstra developed the algorithm without a computer, and later recalled designing it in about twenty minutes.
// THE BASIC IDEA

Finding the cheapest route

Imagine a network of routers. Each connection has a cost. Your task is to calculate the lowest total cost from one router to every other router.

The algorithm:

  1. Set the starting router's distance to 0. All others begin at infinity.
  2. Select the unvisited router with the lowest known distance.
  3. Check whether travelling through it improves the distance to its neighbours.
  4. Mark that router as visited.
  5. Repeat until all reachable routers have been processed.

The algorithm considers total path cost, not simply the cheapest next link.

// ROUTING IN THE REAL WORLD

Where does OSPF fit in?

OSPF (Open Shortest Path First) is a link-state routing protocol. Routers exchange information about the network topology and build a link-state database.

Each router runs a shortest-path-first calculation using Dijkstra's algorithm to build a shortest-path tree rooted at itself. This information helps determine the routes installed in its routing table.

Remember: Dijkstra calculates paths. A router forwards packets using forwarding information derived from its routing table. These are related but different operations.

// CHALLENGES

Think before revealing

CHALLENGE 01 — Cheapest link?

Why is choosing the cheapest outgoing link at every step not always enough to find the cheapest complete route?

Reveal discussion

A cheap first link may lead to expensive later links. Dijkstra compares accumulated costs from the source and systematically updates the best known distances.

CHALLENGE 02 — Routing vs forwarding

Does a router run Dijkstra's algorithm for every IP packet it forwards?

Reveal discussion

No. OSPF calculates routes when building or updating routing information. Packet forwarding uses the forwarding table, normally without recalculating shortest paths for each packet.

CHALLENGE 03 — Link costs

Can the shortest path in terms of hop count be different from the shortest path in terms of OSPF cost?

Reveal discussion

Yes. A path with more hops may have a lower total OSPF cost. OSPF optimizes the sum of link costs, not necessarily the number of routers crossed.
