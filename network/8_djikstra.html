DIJKSTRA'S ALGORITHM

● ROUTING SYSTEM ONLINE_

How does a router find the lowest-cost path through a network? Meet the computer scientist behind the algorithm, then run it yourself. Finally: can a ghost use the same idea to catch Pac-Man?

// THE PERSON BEHIND THE PATH

Edsger W. Dijkstra (1930–2002)

Dijkstra was a Dutch computer scientist. He conceived his shortest-path algorithm in 1956 and published it in 1959. His work influenced programming languages, algorithms, and how we reason about correct software.

His idea: starting from one node, repeatedly select the unvisited node with the lowest known total cost, then see whether traveling through it improves the routes to its neighbors.

Historical note: the algorithm works with non-negative edge weights. Dijkstra received the ACM Turing Award in 1972.

WHY NETWORK ENGINEERS CARE

OSPF is a link-state routing protocol. Routers build a view of the network topology and run a shortest-path-first calculation based on Dijkstra's algorithm.

OSPF cost is a routing metric, not necessarily physical distance or delay.

// BEFORE YOU START

What does "visit" mean?

Think of each router as having a best known total cost from the source. At first we only know one thing for certain: the cost from A to itself is 0. The other costs are ∞ (unknown so far) — this does not mean the physical links cost infinity.

Example: links have costs 2, 7 and 1. We start at A.

FOLLOW THE FIRST TWO VISITS

Initially: A = 0, B = ∞, C = ∞. Nothing is visited.

Visit A: A is the lowest unvisited cost (0). Check its links: B = 0 + 2 = 2; C = 0 + 7 = 7. Now mark A visited.

Visit B: B has the lowest unvisited cost (2). Going via B gives C = 2 + 1 = 3, better than 7. Update C to 3, then mark B visited.

Visit C: Its cost 3 is now final. We have found A → B → C, total cost 3.

Important: "Visited" means the shortest total cost to that router is now final. An unvisited router can have a tentative cost that improves later. Each click in the simulator below performs one full visit: select the lowest-cost unvisited router → inspect its neighbours → update cheaper costs → mark it visited .

CHALLENGE 01 // THINK BEFORE CLICKING

Start at A. Is the direct link A → C the cheapest route to C? Predict the best route and then verify it with the simulator.

Reveal discussion

No. A → B → C costs 2 + 1 = 3, while A → C costs 7. The shortest route can involve more hops.

CHALLENGE 02 // ROUTING VS FORWARDING

Does Dijkstra's algorithm forward an IP packet, or help calculate which path the routing system should prefer?

Reveal discussion

It calculates shortest paths. Forwarding is the separate act of sending an actual packet toward its next hop using the forwarding information derived from routing decisions.

// SIDE QUEST: ARCADE PATHFINDING

Ghost vs. Pac-Man

Imagine a ghost navigating a maze. Every walkable square is a node; each move to an adjacent square costs 1. Walls are not traversable. Dijkstra can find a shortest path to Pac-Man.

🟦 Wall   👻 Ghost   🟡 Pac-Man   Gold = shortest route

The ghost has not calculated its route yet.

This is a simplified pathfinding example, not a claim about the actual AI used in the original Pac-Man arcade game. In an unweighted maze, breadth-first search also finds shortest paths.

CHALLENGE 03 // WHAT CHANGES?

If some tiles cost 5 instead of 1, could the ghost prefer a longer route with a lower total cost?

Reveal discussion

Yes. Dijkstra minimizes total weight, not necessarily the number of steps. With equal weights, a shortest-cost path is also a shortest-step path.

// TAKEAWAYS

Three things to remember

01 / Dijkstra computes shortest paths using cumulative, non-negative link costs.

02 / OSPF uses shortest-path-first calculations, but calculating a route is not the same as forwarding a packet.

03 / The same graph idea works for networks, maps, and mazes.
