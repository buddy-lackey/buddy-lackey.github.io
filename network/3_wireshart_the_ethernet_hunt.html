WIRESHARK: ETHERNET HUNT

Nu lämnar vi de fiktiva paketen. Starta Wireshark och verifiera Ethernet, ARP och MAC-adresser i trafik från din egen dator.

MÅL
Göra en riktig capture, generera kontrollerad trafik och hitta Ethernet-header, ARP, source/destination MAC, broadcast och EtherType.
DU BEHÖVER

Wireshark, ett aktivt nätverksinterface och en annan nåbar IPv4-adress på ditt lokala nät. Kör kommandon som kräver förhöjda rättigheter endast där kursmiljön tillåter det.

Phase 1 — establish identity

Innan capture: identifiera ditt interface.

Windows:
ipconfig /all
arp -a

Linux:
ip addr
ip neigh
CHALLENGE 1

Skriv ned:

Din IPv4-adress: __________________
Din MAC-adress:  __________________
En lokal mål-IP: __________________

Phase 2 — start capture

Starta Wireshark på rätt interface. Använd inget displayfilter ännu. Generera sedan lite lokal trafik genom att pinga den lokala mål-IP-adressen.

ping <lokal-mål-IP>
CHALLENGE 2

Stoppa capture. Kan du hitta ICMP-trafiken? Klicka på en frame och expandera Ethernet II. Notera source och destination MAC.

REVEAL DISCUSSION

Ethernet II visar lager-2-adresserna. IP-delen längre ned i packet details visar lager-3-adresserna. Båda finns i samma kapslade överföring.

Phase 3 — force an ARP observation

Om kursmiljön tillåter det kan du rensa relevant ARP-cache och sedan pinga en lokal host igen. På Windows kan administratörsrättigheter krävas.

Windows:
arp -d *
ping <lokal-mål-IP>

Linux, exempel:
ip neigh
ping <lokal-mål-IP>

På Linux behöver du inte rensa hela neighbor-tabellen om du inte vill; målet är att fånga en ARP-resolution som faktiskt sker.

Phase 4 — hunt ARP

Wireshark display filter:
arp
CHALLENGE 3
  1. Hitta en ARP Request.
  2. Vad är Ethernet source MAC?
  3. Vad är Ethernet destination MAC?
  4. Vad frågar ARP-paketet efter?
  5. Hitta om möjligt motsvarande ARP Reply.
REVEAL

En typisk ARP Request använder destination FF:FF:FF:FF:FF:FF eftersom avsändaren ännu inte känner den sökta hostens MAC. Reply kan sedan skickas unicast tillbaka.

Phase 5 — hunt broadcast

eth.dst == ff:ff:ff:ff:ff:ff
CHALLENGE 4

Hur många broadcast-frames hittar du? Vilka protokoll använder dem i just din capture? Välj en och dokumentera source MAC och protokoll.

Phase 6 — EtherType

Markera en IPv4-frame och en ARP-frame. Expandera Ethernet II och jämför Type-fältet.

CHALLENGE 5

Verifiera om du hittar:

IPv4 → 0x0800
ARP  → 0x0806

Om du har IPv6-trafik, kontrollera även dess EtherType.

REVEAL
IPv4 = 0x0800
ARP  = 0x0806
IPv6 = 0x86DD

Phase 7 — compare layers

CHALLENGE 6

Välj ett IPv4-paket och fyll i:

Ethernet source MAC:      __________________
Ethernet destination MAC: __________________
IPv4 source:              __________________
IPv4 destination:         __________________

Förklara varför samma frame innehåller både MAC- och IP-adresser.

Phase 8 — investigation

CHALLENGE 7

Använd minst två displayfilter från labben och hitta:

  1. en broadcast-frame,
  2. en unicast-frame,
  3. en ARP-frame,
  4. en IPv4-frame.

För varje vald frame: ange source MAC, destination MAC och vilket protokoll som ligger ovanpå Ethernet.

Final questions

FINAL
  1. Vilket fält i Ethernet-headern berättar vad payload innehåller?
  2. Varför syns en ARP Request ofta som broadcast?
  3. Vad är skillnaden mellan MAC-adresserna och IP-adresserna du såg?
  4. Vad kan du nu verifiera i Wireshark som tidigare bara var teori?
REVEAL FINAL DISCUSSION

EtherType identifierar payload-protokollet. ARP Request kan använda broadcast när avsändaren söker en okänd MAC på LAN:et. MAC hör till Ethernet/L2 medan IP hör till L3. Capture visar kapslingen konkret.
