NETWORK BOSS
BYGG AVDELNINGSNÄTET

LEKTION 4 · PACKET TRACER · LAGER 1 OCH 2 · 60–90 MIN

CASE FILE: BAAL-200

I lektion 1 ritade du ett nät för ett företag med 200 anställda: HR, ekonomi, produktion och IT. Nu ska du bygga den del av lösningen som hanterar kablar, switchning och VLAN. Företaget behöver senare Internet, Wi-Fi och interna tjänster. Dessa krav finns kvar, men dagens uppdrag är ett fungerande och segmenterat lager 2-nät.

YOUR ROLE: Network Architect. Leverera ett Packet Tracer-projekt och bevis på att nätet fungerar som avsett.

Arbeta i par. En person konfigurerar och den andra granskar. Byt roller efter uppdrag 3. De åtta datorerna representerar grupper av användare; du behöver inte lägga in 200 klienter.

BASIC // DESIGN 01

FRÅN SKISS TILL KABLAR

  1. Öppna din fysiska och logiska skiss från lektion 1. Om skisserna saknas, gör en enkel skiss utifrån företagets fyra avdelningar.
  2. Skapa ett nytt Packet Tracer-projekt med två 2960-switchar och åtta PC. Döp switcharna till S1 och S2.
  3. Koppla fyra datorer till varje switch enligt tabellen nedan. Använd datorns FastEthernet0 och Copper Straight-Through.
  4. Koppla S1 Fa0/1 till S2 Fa0/1 med Copper Cross-Over eller automatiskt kabelval. Använd en enda länk mellan switcharna.
HR-A · EKO-A · PROD-A · IT-A Accessportar på S1
S1 ↔ S2 Fa0/1 i båda ändar
HR-B · EKO-B · PROD-B · IT-B Accessportar på S2

CHECKPOINT: rätt namn och portar, en switchlänk och gröna länkar efter portarnas startförlopp.

Företaget vill hålla avdelningarnas lager 2-trafik åtskild. Använd denna adressplan som testverktyg. Alla datorer har mask 255.255.255.0; lämna gateway och DNS tomma.

HR 10 Fa0/2 HR-A: 172.17.10.11 HR-B: 172.17.10.12
Ekonomi 20 Fa0/3 EKO-A: 172.17.20.11 EKO-B: 172.17.20.12
Produktion 30 Fa0/4 PROD-A: 172.17.30.11 PROD-B: 172.17.30.12
IT 40 Fa0/5 IT-A: 172.17.40.11 IT-B: 172.17.40.12
  1. På båda switcharna: skapa VLAN 10, 20, 30 och 40 med namnen HR, EKONOMI, PRODUKTION och IT.
  2. Konfigurera datorportarna som accessportar i rätt VLAN.
  3. På varje dator: ange adressen via Desktop → IP Configuration.
  4. Verifiera portarnas VLAN med show vlan brief.

Exempel för HR på S1. Upprepa med rätt värden för övriga avdelningar och på S2.

INTERMEDIATE // DESIGN 03

FYRA VLAN ÖVER EN KABEL

HR på S1 ska nå HR på S2. Detsamma gäller övriga avdelningar. Länken måste bära alla fyra VLAN utan att blanda dem.

  1. Skapa VLAN 99 med namnet NATIVE på båda switcharna. Det ska inte ha några datorer eller IP-adresser.
  2. Konfigurera Fa0/1 som trunk på båda switcharna.
  3. Använd Native VLAN 99 och tillåt VLAN 10, 20, 30, 40 och 99.
  4. Kontrollera länken med show interfaces trunk och show interfaces fastEthernet0/1 switchport.
Ledtråd: trunk på båda ändar 
configure terminal
vlan 99
 name NATIVE
exit
interface fastEthernet0/1
 switchport mode trunk
 switchport trunk native vlan 99
 switchport trunk allowed vlan 10,20,30,40,99
 no shutdown
exit
end
show interfaces trunk

2960 använder 802.1Q. Du behöver inte välja encapsulation med ett separat kommando.

CHECKPOINT: trunken är operativt uppe och avdelningarnas VLAN är tillåtna och aktiva på båda switcharna.

CHALLENGE // DESIGN 04

BEVISA ATT NÄTET FUNGERAR

Öppna Desktop → Command Prompt på A-datorerna. Testa följande. Upprepa ping efter att ARP och portarnas startförlopp hunnit bli klara.

Från Ping till Förväntat
HR-A 172.17.10.12 Fungerar
EKO-A 172.17.20.12 Fungerar
PROD-A 172.17.30.12 Fungerar
IT-A 172.17.40.12 Fungerar
HR-A 172.17.20.12 Misslyckas: annat subnät, ingen gateway

Det sista testet bevisar inte ensamt VLAN-separation. Datorn saknar också en route till det andra subnätet. Gör därför ett starkare test:

  1. Ändra tillfälligt EKO-B:s IP till 172.17.10.22/24. Behåll porten i VLAN 20 och gateway tom.
  2. Pinga 172.17.10.22 från HR-A. Det ska misslyckas trots samma IP-subnät.
  3. Återställ EKO-B till 172.17.20.12/24. Verifiera ekonomins kommunikation igen.

CHALLENGE // DESIGN 05

FÖLJ BROADCASTEN

  1. Byt till Simulation och välj ARP och ICMP i Edit Filters.
  2. Töm HR-A:s ARP-cache med arp -d i datorns Command Prompt och pinga HR-B. Om versionen inte stöder kommandot, starta om den simulerade datorn och kontrollera IP-inställningen före testet.
  3. Använd Capture/Forward. Följ ARP-förfrågan över S1 och S2 och se vilka datorer som får den.
  4. Undersök destinations-MAC i ARP-förfrågan och jämför med ICMP-trafiken efter ARP-svaret.
  5. På switcharna: undersök show mac address-table efter testerna.

CHALLENGE+ // DESIGN 06

INCIDENT: PRODUKTIONEN ÄR BORTA

En ändring har gjort att produktionsdatorerna inte längre når varandra. Övriga avdelningar fungerar.

  1. Skapa felet på S1 genom att ändra trunkens tillåtna lista till 10,20,40,99.
  2. Byt roller. Den som inte gjorde ändringen felsöker med ping, portarnas VLAN och trunkens inställningar.
  3. Förklara varför länken kan vara grön trots att produktionens trafik inte passerar.
  4. Återställ till 10,20,30,40,99 och testa alla fyra avdelningar igen.
Ledtråd: ändra och återställ 
configure terminal
interface fastEthernet0/1
 switchport trunk allowed vlan 10,20,40,99
end
show interfaces trunk

BOSS QUESTION // Vad händer när länken går ner?

Förutsäg resultatet om kabeln mellan S1 och S2 tas bort. Testa sedan och återanslut kabeln. Skilj mellan att en dator har fysisk länk till sin switch och att den kan nå sin avdelningskollega på den andra switchen.

Redundans diskuteras på skissen. Lägg inte till extra switchlänkar i denna labb; hantering av lager 2-loopar behöver behandlas först.

NEXT MISSION // Server och Internet

Ledningen frågar: ”Alla avdelningar behöver en gemensam server och Internet. Varför fungerar inte det ännu?” Markera i den logiska skissen var en framtida lager 3-funktion och säkerhetskontroll skulle kunna placeras. Konfigurera dem inte nu.

Efter genomförandet: jämför ditt resonemang

Avdelningarna är separata broadcastdomäner. Accessportarna placerar otaggad datortrafik i ett VLAN. Trunken transporterar avdelningarnas trafik taggad, med respektive VLAN-ID. Native VLAN 99 är normalt otaggat och används inte av datorerna här.

ARP i HR:s VLAN når HR på båda switcharna men inte ekonomins portar. MAC-tabellen kopplar MAC-adresser och VLAN till portar; ARP-tabellen kopplar lokala IPv4-adresser till MAC-adresser. En fungerande trunk ger ingen routing mellan VLAN.

En grön fysisk länk bevisar inte att alla VLAN får passera. Om switchlänken bryts försvinner kommunikationen mellan switcharna, men respektive switch kan fortfarande vidarebefordra inom sina lokala VLAN. För kommunikation mellan olika VLAN behövs routing på lager 3. Brandvägg eller andra regler kan sedan styra vilken trafik som tillåts. VLAN-separation i sig ersätter inte sådana regler.
