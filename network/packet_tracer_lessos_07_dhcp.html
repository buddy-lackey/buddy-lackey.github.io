ALEF-93 / LECTURE 07 / PACKET TRACER

DHCP: ACROSS THE VLANs

● ADDRESS ALLOCATION ONLINE_

One server. Three client networks. Make the broadcasts cross the boundary.

ONE LAN THREE VLANs RELAY ROUTER OPTION

Mission briefing

Start with a single switched LAN. Then move three PCs into separate VLANs, put the DHCP server in a server VLAN, and implement DHCP relay and inter-VLAN routing.

Main path: Server-PT, three PC-PT devices, a 2960 for part 1 and a 3560 for part 2. Allow 60–90 minutes. The router-on-a-stick path is an optional extension.

Build first. Predict the result. Test it. Open the discussion when you need a hint or want to compare your explanation.

MISSION 01

One LAN. One DHCP server.

Build a network using one 2960 switch, one Server-PT and three PC-PT devices. Connect all devices using copper straight-through cables. Leave the switch ports in VLAN 1.

  • Server → Fa0/1
  • PC-A → Fa0/2
  • PC-B → Fa0/3
  • PC-C → Fa0/4

On Server-PT, open Desktop → IP Configuration and select Static: 

IP address:      192.168.10.10
Subnet mask:     255.255.255.0
Default gateway: leave unset (0.0.0.0)

Do we need a router for these devices to communicate?

Reveal discussion / configuration

No. All devices are in the same IPv4 subnet and VLAN. They can communicate directly using Ethernet and ARP. A default gateway becomes necessary when they communicate outside their subnet.

MISSION 02

Build the first address pool

On the server, open Services → DHCP, select the connected interface if asked, and turn the service On. Configure a pool: 

Pool name:       LAN10
Default gateway: 0.0.0.0
DNS server:      0.0.0.0
Start IP address:192.168.10.100
Subnet mask:     255.255.255.0
Maximum users:   50

Click Add, or Save when editing an existing pool. Remove or edit any default pool that could overlap. No DNS service is needed for this lab because all tests use IP addresses.

On each PC, open Desktop → IP Configuration → DHCP. Record the assigned address and mask. Ping the other PCs and the server.

Why must the server’s address stay outside the client allocation range?

Reveal discussion / configuration

Clients should receive addresses in 192.168.10.100–149, with mask 255.255.255.0. The exact allocation order can vary. Keeping 192.168.10.10 outside the pool avoids the DHCP server assigning its own address to a client. Repeat an initial ping if ARP resolution delays the first response.

MISSION 03

Catch DORA

  1. Switch to Simulation mode.
  2. In Edit Filters, select DHCP. Some versions group related traffic under DHCP/BOOTP.
  3. On one PC, select Static and then DHCP to request a fresh configuration.
  4. Use Capture/Forward and open the packet details.

Find Discover, Offer, Request and ACK. Record the source/destination IPv4 addresses and UDP ports of the initial Discover. Which messages come from the client?

If the client reuses an existing lease, you may see a shorter exchange. A newly added PC is an easy way to observe a first-time exchange.

Reveal discussion / configuration

The usual first-time sequence is Discover → Offer → Request → ACK. The client sends Discover and Request. Initial Discover normally uses 0.0.0.0:68 → 255.255.255.255:67. A client can broadcast before it has an assigned IPv4 address. Offer and ACK are not always broadcast; inspect what the simulation actually shows.

MISSION 04

Upgrade to three VLANs

Save the first topology as dhcp_step1.pkt. Create a second copy as dhcp_step2.pkt. Replace the 2960 with a 3560 multilayer switch. Use this port plan:

Device Port VLAN Subnet Gateway
PC-A Fa0/2 10 192.168.10.0/24 192.168.10.1
PC-B Fa0/3 20 192.168.20.0/24 192.168.20.1
PC-C Fa0/4 30 192.168.30.0/24 192.168.30.1
Server Fa0/1 99 192.168.99.0/24 192.168.99.1

Change the server’s static address to 192.168.99.10/24, with default gateway 192.168.99.1. Configure the VLANs and access ports. Keep DHCP clients waiting until the new pools and relay are ready.

All four links are access links. A trunk is not needed here because each attached endpoint belongs to one VLAN and routing happens inside the multilayer switch.

MISSION 05

Enable routing — then predict DHCP

Create an SVI with the gateway address for each VLAN and enable IPv4 routing. Do not configure DHCP relay yet.

Temporarily set PC-B to 192.168.20.50/24, gateway 192.168.20.1. Verify that it can ping 192.168.99.10, then switch PC-B back to DHCP.

Does working inter-VLAN routing automatically make the DHCP broadcast reach the server?

Reveal discussion / configuration 
configure terminal
ip routing

interface vlan 10
 ip address 192.168.10.1 255.255.255.0
 no shutdown

interface vlan 20
 ip address 192.168.20.1 255.255.255.0
 no shutdown

interface vlan 30
 ip address 192.168.30.1 255.255.255.0
 no shutdown

interface vlan 99
 ip address 192.168.99.1 255.255.255.0
 no shutdown

end
show ip interface brief
show ip route

Routing allows unicast traffic between connected subnets, but does not normally forward a limited broadcast to another subnet. An SVI requires its VLAN to exist and an active forwarding port in that VLAN. Wait for link/STP convergence before testing.

MISSION 06

Three pools. One server.

On Server-PT, open Services → DHCP. Edit the existing LAN10 pool and add LAN20 and LAN30. Keep DHCP On.

Pool Start address Mask Gateway Users
LAN10 192.168.10.100 255.255.255.0 192.168.10.1 50
LAN20 192.168.20.100 255.255.255.0 192.168.20.1 50
LAN30 192.168.30.100 255.255.255.0 192.168.30.1 50

Set DNS to 0.0.0.0 for each pool. Save each change. The server VLAN uses static addressing and needs no DHCP pool for this exercise.

What would happen if LAN20 supplied 192.168.10.1 as its gateway?

Reveal discussion / configuration

The client would receive a gateway outside its own /24 subnet, making normal off-subnet communication fail. DHCP must provide settings appropriate to the client’s subnet, not the server’s subnet.

MISSION 07

Relay the request

On the L3 switch, configure ip helper-address 192.168.99.10 on each client SVI. Request DHCP again on all PCs.

Verify that PC-A gets a VLAN 10 address, PC-B a VLAN 20 address and PC-C a VLAN 30 address. How can the server choose the right pool when every request reaches the same server IP?

Reveal discussion / configuration 
configure terminal

interface vlan 10
 ip helper-address 192.168.99.10

interface vlan 20
 ip helper-address 192.168.99.10

interface vlan 30
 ip helper-address 192.168.99.10

end
copy running-config startup-config

The helper belongs on the interface that receives the client broadcast. The relay forwards the request to the server and supplies the client-side subnet context through the relay-agent address (giaddr). The server uses that information to select a matching pool. You do not need a helper on VLAN 99 for these clients.

MISSION 08

Prove the whole chain

  1. On every PC, run ipconfig /all and record IP, mask and gateway.
  2. Ping the local gateway, then 192.168.99.10, then each of the other PCs.
  3. On the switch, inspect the VLANs, SVIs and routing table.
  4. In Simulation mode, request DHCP on a client and follow the packet through the relay to the server.
  5. Filter for ARP and ICMP, then ping between VLANs.

Deliver a screenshot of the topology, the three client configurations and successful inter-VLAN pings. Explain the roles of DHCP, ARP and ICMP in three sentences.

Reveal discussion / configuration 
show vlan brief
show ip interface brief
show ip route
show ip arp
show running-config

DHCP provides client addressing and gateway settings. ARP resolves the local next-hop MAC; for a remote subnet, this is the gateway MAC. ICMP Echo Request/Reply tests IP reachability. The L3 switch routes the packet and builds a new Ethernet frame for the outgoing VLAN. Its ARP table and MAC table have different purposes.

MISSION 09

Break one thing. Explain the symptom.

Save a working copy first. Make one change at a time, test, then restore it:

  1. Remove the helper from VLAN 20 and make PC-B request a fresh lease.
  2. Restore the helper, then remove ip routing.
  3. Restore routing, then assign PC-C’s access port to VLAN 20 instead of 30. Request DHCP again.

For each fault, predict the outcome before testing. An existing DHCP lease may remain usable: use ipconfig /release then ipconfig /renew in this isolated lab, or add a fresh test PC.

Reveal discussion / configuration

Without the helper, a fresh VLAN 20 request cannot reach the remote DHCP server through the intended relay. Without IP routing, cross-subnet communication fails; do not assume that an existing client lease immediately disappears. A client moved into VLAN 20 should receive a VLAN 20 lease on a new allocation: DHCP follows the network attachment, not the PC’s name. 

configure terminal
interface vlan 20
 no ip helper-address 192.168.99.10
end

! Restore before continuing:
configure terminal
interface vlan 20
 ip helper-address 192.168.99.10
exit
no ip routing
end

! Restore routing:
configure terminal
ip routing
end
MISSION 10

Alternative route: router-on-a-stick

Optional: instead of the 3560, use a 2960 and a 1941 router. Retain the same VLANs, access ports, server settings and DHCP pools. Connect switch Gi0/1 to router Gi0/0.

Create VLANs 10, 20, 30 and 99 on the 2960 as above. Configure the uplink as a trunk. On the router, create one subinterface per VLAN and place the helpers on the three client subinterfaces.

Interface names vary by router model; adapt them to your device. Which link carries traffic for all four VLANs?

Reveal discussion / configuration

2960 uplink:

enable
configure terminal

interface gigabitEthernet0/1
 switchport mode trunk
 switchport trunk allowed vlan 10,20,30,99
 no shutdown

end

1941 router:

enable
configure terminal

interface gigabitEthernet0/0
 no ip address
 no shutdown

interface gigabitEthernet0/0.10
 encapsulation dot1Q 10
 ip address 192.168.10.1 255.255.255.0
 ip helper-address 192.168.99.10

interface gigabitEthernet0/0.20
 encapsulation dot1Q 20
 ip address 192.168.20.1 255.255.255.0
 ip helper-address 192.168.99.10

interface gigabitEthernet0/0.30
 encapsulation dot1Q 30
 ip address 192.168.30.1 255.255.255.0
 ip helper-address 192.168.99.10

interface gigabitEthernet0/0.99
 encapsulation dot1Q 99
 ip address 192.168.99.1 255.255.255.0

end
copy running-config startup-config

The switch–router trunk carries the four VLANs using 802.1Q tagging. The router subinterfaces provide the gateways and relay function. Leave the L2 switch without these gateway addresses. Test using the same verification steps as the main path.
