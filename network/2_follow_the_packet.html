CHALLENGE 01BAALSTORM

Follow the Packet

Mål: Skilj på MAC-adress, IP-adress och portnummer och förklara hur data kapslas.

PC1 ansluter till en webbserver på Internet:

PC1
IP:   192.168.10.25
MAC:  AA:AA:AA:AA:AA:25

Default Gateway
IP:   192.168.10.1
MAC:  BB:BB:BB:BB:BB:01

Web Server
IP:   203.0.113.80
TCP:  443

PC1 öppnar https://203.0.113.80/. Följande information finns i trafiken:

Ethernet
  Destination: BB:BB:BB:BB:BB:01
  Source:      AA:AA:AA:AA:AA:25

IPv4
  Destination: 203.0.113.80
  Source:      192.168.10.25

TCP
  Destination Port: 443
  Source Port:      51832
UPPGIFT
  1. Vilka adresser hör till lager 2?
  2. Vilka adresser hör till lager 3?
  3. Vad betyder TCP-port 443 respektive 51832?
  4. Varför är destination MAC routerns MAC och inte webbserverns MAC?
  5. Vilken adressinformation måste bytas när trafiken lämnar det lokala Ethernet-segmentet?
  6. Ordna: HTTP-data, TCP-segment, IP-paket, Ethernet-frame, bitar.

Final challenge

Vilket påstående beskriver kommunikationen bäst?

A  MAC-adresserna används hela vägen till webbservern.
B  IP-adresserna används bara på det lokala nätverket.
C  MAC-adresser används hop-by-hop medan IP används för kommunikationen
   mellan avsändare och destination.
REVEAL DISCUSSION

C. Ethernet levererar framen på den aktuella länken. IP används för att adressera paketet genom det routade nätverket. När en router vidarebefordrar trafik tas den inkommande L2-framen bort och en ny L2-frame skapas för nästa länk.

Ordningen nedåt i stacken är: HTTP-data → TCP-segment → IP-paket → Ethernet-frame → bitar.

CHALLENGE 02BAALSTORM

The Network Is Broken

Mål: Resonera om lokalt nät, ARP, default gateway och routing.

PC-ALPHA
IP address:      192.168.10.25
Subnet mask:     255.255.255.0
Default gateway: 192.168.10.1
DNS:             192.168.10.53

C:\> ping 192.168.10.40
Reply from 192.168.10.40

C:\> ping 192.168.20.40
Destination host unreachable.

C:\> arp -a
192.168.10.1     00-aa-bb-cc-dd-01
192.168.10.40    00-aa-bb-cc-dd-40
ANALYSERA
  1. Vilken destination är lokal för PC-ALPHA?
  2. Vilken destination kräver routing?
  3. Varför behöver PC:n inte känna till MAC-adressen för 192.168.20.40?
  4. Vilken MAC-adress behöver den istället?

Du får sedan tillgång till routern:

Router G0/0
IP address: 192.168.100.1/24
HITTA FELET: Varför fungerar inte kommunikationen till andra nät?
REVEAL DISCUSSION

PC:n är konfigurerad med 192.168.10.1 som default gateway, men routerns interface är 192.168.100.1/24. PC:n och dess gateway måste kunna kommunicera lokalt. Trafik till 192.168.20.40 skickas därför aldrig korrekt till en router.

LAB 04PACKET TRACER

Across the Router

Mål: Upptäck vad som händer med L2- och L3-information när ett paket routas.

PC1 ─ SW1 ─ R1 ─ SW2 ─ PC2

PC1       192.168.1.10/24   GW 192.168.1.1
R1 G0/0   192.168.1.1/24
R1 G0/1   192.168.2.1/24
PC2       192.168.2.10/24   GW 192.168.2.1
UPPGIFT
  1. Konfigurera topologin. Glöm inte att routerinterfacen måste vara aktiva.
  2. Verifiera med ping 192.168.2.10 från PC1.
  3. Byt till Simulation Mode och följ ett ICMP Echo Request.
  4. Inspektera L2- och L3-information före och efter R1.
LänkSource MACDestination MACSource IPDestination IP
PC1 → R1
R1 → PC2
BREAK IT: Ta bort default gateway från PC1. Testa först en adress i 192.168.1.0/24 och därefter PC2. Förklara resultatet.
REVEAL DISCUSSION

IP-källan och IP-destinationen är normalt desamma genom denna enkla topologi. Ethernet-adresseringen gäller däremot den aktuella länken. Routern tar bort den inkommande L2-framen och kapslar IP-paketet i en ny frame för nästa länk.

LAB 05FORTINET / FORTISWITCH

Se Ethernet på riktigt

Mål: Jämför datorns ARP-cache med switchens MAC-tabell och verifiera trafiken i Wireshark.

PC1 ─ port 1 ┐
             │
         FortiSwitch
             │
PC2 ─ port 2 ┘

PC1  192.168.10.10/24
PC2  192.168.10.20/24

Exakta CLI-kommandon kan skilja mellan FortiSwitch-modell, FortiSwitchOS-version och standalone/FortiLink-management. Använd GUI eller de kommandon som gäller för labbets switch.

UPPGIFT
  1. Verifiera att båda switchportarna är uppe och ligger i samma VLAN.
  2. Hitta switchens MAC address table och notera vilken MAC som lärts på respektive port.
  3. Rensa eller kontrollera ARP-cachen på PC1.
  4. Starta Wireshark på PC1 och pinga PC2.
  5. Identifiera ARP Request/Reply och ICMP Echo Request/Reply.
  6. Jämför MAC-adresserna i Wireshark med switchens MAC-tabell.
  7. Flytta PC2 till en annan accessport, generera trafik igen och observera vad som händer i MAC-tabellen.

Förklara skillnaden

PC ARP-cache:        IP address  ──> MAC address
Switch MAC-table:    MAC address ──> switchport
REVEAL DISCUSSION

ARP hjälper en IPv4-host att hitta rätt L2-adress. Switchen lär sig däremot var en MAC-adress finns genom source MAC i inkommande frames och använder sin MAC-tabell när den vidarebefordrar frames.

Hur vet switchen vart framen ska?

              │

Switch# show mac address-table dynamic

Identifiera vilken MAC-adress som finns på respektive port.

CHALLENGE: Hur lärde sig switchen att PC1:s MAC-adress finns på Gi1/0/1? Vilket fält i Ethernet-framen använder den för inlärningen?
STEG 3 — GLÖM OCH LÄR OM
Switch# clear mac address-table dynamic
Switch# show mac address-table dynamic

# Generera trafik mellan datorerna igen.

Switch# show mac address-table dynamic
REVEAL DISCUSSION

Switchen lär sig från source MAC address på frames som kommer in på en port. När destinationens MAC är känd kan framen skickas mot rätt port istället för att floodas till övriga relevanta portar.
