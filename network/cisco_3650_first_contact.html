BASIC // MISSION 01

Fråga

Är CONSOLE och MGMT två namn på samma typ av anslutning?

Nej.

CONSOLE är en lokal seriell managementväg och kräver ingen IP-adress. MGMT är en Ethernet-managementport och använder IP-kommunikation.
BASIC // MISSION 02

// CONSOLE FIRST CONTACT

Anslut Fortinet-consolekabeln mellan datorn och Catalyst-switchens CONSOLE-port.

LAPTOP │ │ Fortinet RJ45 console cable │ ▼ CONSOLE │ ▼ CATALYST 3650

Tera Term

Connection: Serial COM port: den port Windows tilldelat kabeln Speed: 9600 baud Data: 8 bit Parity: none Stop: 1 bit Flow: none

Tryck Enter ett par gånger.

Switch>

Gå till privileged EXEC mode:

Switch> enable Switch#
Lägg märke till att console fungerade utan att datorn behövde känna till switchens management-IP.
Om IP-konfigurationen är trasig kan console fortfarande ge administrativ åtkomst. Därför är console viktig vid installation, felsökning och recovery.
BASIC // MISSION 03

// CLI RECON

Vi börjar read-only. Ta reda på vad switchen faktiskt är.

Switch# show version Switch# show switch Switch# show ip interface brief Switch# show interfaces status
Dokumentera:

Förväntad managementinformation

Interface: GigabitEthernet0/0 IP: 192.168.1.99 Mask: 255.255.255.0
Gi0/0 är managementinterfacet. Det är inte samma sak som de vanliga switchportarna Gi1/0/1, Gi1/0/2...
INTERMEDIATE // MISSION 04

// MGMT FIRST CONTACT

Låt console-kabeln sitta kvar. Anslut nu även en vanlig Ethernetkabel mellan datorn och switchens MGMT-port.

LAPTOP / \ / \ SERIAL / \ ETHERNET / \ ▼ ▼ CONSOLE MGMT │ Gi0/0 │ 192.168.1.99 CATALYST 3650

Konfigurera datorns Ethernetinterface manuellt, exempelvis:

IP address: 192.168.1.10 Subnet mask: 255.255.255.0 Gateway: lämnas tom i detta isolerade labb

Testa sedan:

C:\> ping 192.168.1.99

Tänk innan du testar

Varför kan 192.168.1.10 kommunicera direkt med 192.168.1.99 utan en router?

Med /24-mask ligger båda adresserna i nätverket 192.168.1.0/24. Kommunikation inom samma IP-nät behöver inte gå via en router.

CHALLENGE // MISSION 09

// PACKET TRACER MIRROR

Nu ska du koppla det du sett på riktig hårdvara till Cisco Packet Tracer.

Packet Tracer är en modell av Cisco-nätverk. Den är inte en exakt emulator av just vår Catalyst 3650, vår IOS XE-version eller vårt WebUI.

Del A — Console

Placera en PC/laptop och en lämplig Cisco-switch i Packet Tracer. Anslut console-kabeln.

REAL LAB PACKET TRACER Fortinet console cable → Console cable Tera Term → Desktop → Terminal Physical CONSOLE port → Console port IOS CLI → Simulated IOS CLI

Öppna Desktop → Terminal på Packet Tracer-PC:n.

Switch> Switch> enable Switch# show ip interface brief

Del B — Ethernet

Anslut även en Ethernetförbindelse och jämför den med den fysiska managementanslutningen.

OPTIONAL INCIDENT

// NETWORK WORKS — APPLICATION FAILS

Under installation av en nätverksenhet kan följande situation uppstå:

PING 192.168.1.99 [ OK ] HTTPS SERVER [ ENABLED ] BROWSER HTTPS [ FAIL ]

Betyder det att nätverket är trasigt?

Inte nödvändigtvis.

Om ping fungerar har vi redan bevis för IP-kommunikation. HTTPS kan ändå misslyckas högre upp i kommunikationskedjan, exempelvis på grund av TLS- eller certifikatproblem.

Viktig princip:
Layer 3 connectivity ≠ Application success
