WIRESHARK:
INSIDE THE PACKET

Analysera riktig trafik från din egen dator och hitta Ethernet, IP, TCP/UDP och applikationsprotokoll i praktiken.

MÅL
Efter övningen ska du kunna välja ett paket i Wireshark, identifiera information från lager 2, 3 och 4 och förklara hur protokollen är kapslade i varandra.

1. Ta reda på vem du är

Öppna Command Prompt eller PowerShell:

ipconfig /all
arp -a
Skriv ned din IPv4-adress, subnet mask, default gateway och MAC-adress (Physical Address).

2. Starta en capture

  1. Starta Wireshark.
  2. Välj det interface som faktiskt används, exempelvis Ethernet eller Wi-Fi.
  3. Starta capture.

Det kommer sannolikt mycket trafik. Det är normalt — vi använder display filters för att hitta rätt paket.

3. Generera trafik

Medan Wireshark spelar in:

ICMP

ping 8.8.8.8

DNS

nslookup example.com

Webb

Öppna en vanlig HTTPS-webbplats i webbläsaren. Stoppa därefter capture.

4. Hitta protokollen

Prova display filters ett i taget:

arp
icmp
dns
tcp
udp
UPPGIFT: Vilka protokoll hittar du? Vilka genererade du medvetet och vilka fanns där ändå?

CHALLENGE: Du pingar 8.8.8.8, men destination MAC är normalt inte MAC-adressen till 8.8.8.8. Vems MAC-adress är det sannolikt — och varför?
REVEAL DISCUSSION
8.8.8.8 ligger normalt utanför ditt lokala nät. Ethernet-framen skickas därför till nästa hopp, normalt default gateway. IP-paketets destination är fortfarande 8.8.8.8.

7. DNS — TCP eller UDP?

dns

Välj DNS-frågan från nslookup och skriv protokollkedjan du faktiskt ser:

Ethernet → IP → ______ → DNS

DNS kan använda både UDP och TCP. Svara utifrån din egen capture.

8. HTTPS

tcp.port == 443

Välj ett paket från webbtrafiken. Jämför med DNS-paketet: vilka lager är lika och vilka protokoll skiljer sig?

CHALLENGE: Varför kan Wireshark visa MAC-adresser, IP-adresser och TCP-portar även när webbkommunikationen är krypterad med TLS?
REVEAL DISCUSSION
TLS skyddar applikationsdata. Underliggande Ethernet-, IP- och TCP-information måste fortfarande vara tillgänglig för att trafiken ska kunna levereras.
