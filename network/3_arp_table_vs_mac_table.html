TWO TABLES

Samma Ethernetkommunikation involverar två tabeller som studenter ofta blandar ihop. Nu separerar vi dem ordentligt.

MÅL
Förstå ARP-cache som IP→MAC och switchens MAC-tabell som MAC→port, samt följa hur båda byggs under en kommunikation.
PC1 (Port 1)             PC2 (Port 7)
IP  192.168.10.10        IP  192.168.10.20
MAC AA:AA:AA:AA:AA:10    MAC BB:BB:BB:BB:BB:20
          \               /
             [ SWITCH ]

PC1 ARP CACHE: EMPTY
SWITCH MAC TABLE: EMPTY

Step 1 — PC1 knows an IP, not a MAC

CHALLENGE 1

PC1 ska skicka ett IPv4-paket till 192.168.10.20 på samma LAN. Vilken information saknas för att skapa Ethernet-framen?

REVEAL

PC1 behöver veta vilken destination-MAC som hör till 192.168.10.20.

Step 2 — ARP Request

Who has 192.168.10.20?
Tell 192.168.10.10

Ethernet destination:
FF:FF:FF:FF:FF:FF
CHALLENGE 2
  1. Varför används broadcast?
  2. Vad kan switchen lära sig redan från ARP Requestens source MAC?
  3. Vilken port eller vilka portar får requesten?
REVEAL

PC1 känner ännu inte PC2:s MAC och frågar därför LAN:et. När framen kommer från P1 kan switchen lära AA:AA:AA:AA:AA:10 → P1. Broadcasten floodas ut på övriga relevanta portar.

Step 3 — ARP Reply

192.168.10.20 is at BB:BB:BB:BB:BB:20
CHALLENGE 3

Efter reply: skriv både PC1:s ARP-cache och switchens MAC-tabell.

REVEAL
PC1 ARP CACHE
192.168.10.20 → BB:BB:BB:BB:BB:20

SWITCH MAC TABLE
AA:AA:AA:AA:AA:10 → P1
BB:BB:BB:BB:BB:20 → P7

Step 4 — actual IPv4 traffic

CHALLENGE 4

PC1 har nu allt den behöver. Beskriv två separata beslut:

  1. Hur bestämmer PC1 destination-MAC?
  2. Hur bestämmer switchen utgående port?
REVEAL

PC1 använder IP→MAC-informationen i ARP-cachen för att skapa framen. Switchen läser frame-destinationen och använder MAC→port-informationen i sin MAC-tabell.

Step 5 — trap question

CHALLENGE 5

Vilken tabell innehåller följande poster?

192.168.10.20 → BB:BB:BB:BB:BB:20
BB:BB:BB:BB:BB:20 → Port 7
REVEAL
IP → MAC   = ARP-cache
MAC → Port = switchens MAC-tabell

Step 6 — clear ARP, keep MAC table

PC1:s ARP-cache rensas men switchens MAC-tabell ligger kvar.

CHALLENGE 6

Kan PC1 omedelbart skapa en unicast Ethernet-frame till PC2 bara för att switchen vet att PC2 finns på Port 7?

REVEAL

Nej. Switchens interna MAC→port-kunskap ersätter inte PC1:s behov av att känna destination-MAC. PC1 behöver åter lösa IP→MAC, exempelvis med ARP.

HOST:   ARP     IP  → MAC
SWITCH: MAC/FDB MAC → PORT
