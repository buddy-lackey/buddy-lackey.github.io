PACKET TRACER LAB 1

PACKET TRACER: SWITCH LEARNING

MÅL
Bygg ett enkelt Ethernet-LAN, använd Simulation Mode och verifiera hur en switch lär source MAC och floodar en okänd destination.
BUILD THIS
PC0 ─────┐
PC1 ─────┼── 2960 Switch
PC2 ─────┘

Exempel:
PC0 192.168.1.10/24
PC1 192.168.1.20/24
PC2 192.168.1.30/24

Ingen router behövs: alla hosts ligger på samma nät.

1 — Build and verify

Koppla datorerna till switchen och konfigurera IPv4-adresserna. Vänta tills länkarna är uppe.

CHALLENGE 1

Notera varje PCs MAC-adress och switchport. Kontrollera switchens MAC-tabell via CLI.

Switch> enable
Switch# show mac address-table

2 — Simulation Mode

Byt till Simulation. Filtrera gärna till ARP och ICMP. Från PC0:

ping 192.168.1.20
CHALLENGE 2

Stega händelserna. Vilket protokoll behöver normalt komma före den första ICMP Echo Request om PC0 ännu inte känner PC1:s MAC?

REVEAL

ARP behövs för att lösa den lokala IPv4-adressen till en destination-MAC innan Ethernet-framen kan skapas.

3 — Watch the switch

CHALLENGE 3

När första framen från PC0 når switchen: vilken MAC kan switchen lära och från vilket fält? Vad händer om destinationen ännu inte finns i MAC-tabellen?

REVEAL

Source MAC lärs på ingressporten. En okänd unicastdestination floodas; broadcast floodas också till övriga portar.

4 — Table after communication

Switch# show mac address-table dynamic
CHALLENGE 4

Kan ni nu hitta både PC0 och PC1? Matcha MAC → port.

5 — Known unicast

Skicka ytterligare trafik mellan PC0 och PC1 efter att tabellen byggts upp.

CHALLENGE 5

Vad är annorlunda när destination-MAC redan finns i tabellen? Behöver switchen skicka unicastframen till PC2:s port?

REVEAL

Known unicast kan filtreras till den kända destinationens port. PC2 behöver inte få den framen.

6 — Clear and repeat

Switch# clear mac address-table dynamic

Upprepa kommunikationen och observera hur tabellen byggs igen.

FINAL

Skriv två regler som sammanfattar hela labben.

REVEAL FINAL
LEARN   FROM SOURCE
FORWARD ON DESTINATION

PACKET TRACER LAB 2

PACKET TRACER: ACROSS THE ROUTER

MÅL
Verifiera att IP-adresser används end-to-end medan Ethernet/MAC gäller per länk, och analysera vad routern gör med lager-2-headern.
BUILD THIS
PC1 ── Switch1 ── Router ── Switch2 ── PC2

LAN 1: 192.168.10.0/24
PC1:   192.168.10.10
R1:    192.168.10.1

LAN 2: 192.168.20.0/24
R2:    192.168.20.1
PC2:   192.168.20.20

Konfigurera PC1 gateway till 192.168.10.1 och PC2 gateway till 192.168.20.1.

1 — Prove the route

PC1> ping 192.168.20.20
CHALLENGE 1

Få kommunikationen att fungera. Vilken enhet måste PC1 skicka den lokala Ethernet-framen till när destination-IP ligger på ett annat nät?

REVEAL

PC1 skickar framen mot sin default gateway, alltså routerns MAC på LAN 1.

2 — Simulation Mode

Byt till Simulation Mode och följ ett ICMP Echo Request från PC1 till PC2.

CHALLENGE 2 — BEFORE ROUTER

Precis innan framen går in i routern från LAN 1, identifiera:

Source IP:      ?
Destination IP: ?
Source MAC:     ?
Destination MAC:?
REVEAL DISCUSSION

IP-källan är PC1 och IP-destinationen PC2. På LAN 1 är source MAC PC1:s MAC och destination MAC routerns LAN-1-interface.

3 — After router

CHALLENGE 3 — AFTER ROUTER

Inspektera samma IP-paket när det skickas ut på LAN 2. Vilka adresser är oförändrade? Vilka lager-2-adresser är nya?

REVEAL

Source/destination IP fortsätter representera PC1→PC2. Routern skickar däremot paketet i en ny Ethernet-frame på LAN 2: source MAC blir routerns LAN-2-MAC och destination MAC blir PC2:s MAC.

4 — The ICMP trap

CHALLENGE 4

Lektionsmaterialet frågar: “Vilket portnummer använder Ping (ICMP)?” Vad är svaret?

REVEAL

ICMP använder inte TCP- eller UDP-portnummer. Det är alltså en avsiktlig fälla om man försöker applicera transportlagrets portbegrepp på ICMP.

5 — ARP on both LANs

CHALLENGE 5

Varför kan ARP behövas på båda sidor om routern trots att det är samma ping som färdas från PC1 till PC2?

REVEAL

Varje Ethernetlänk behöver rätt lokal destination-MAC. PC1 kan behöva lösa gatewayens MAC på LAN 1, och routern kan behöva lösa PC2:s MAC på LAN 2.

6 — Final trace

FINAL

Fyll i utan att öppna tidigare svar:

LAN 1:
Ethernet: PC1 MAC → __________ MAC
IP:       PC1 IP  → PC2 IP

LAN 2:
Ethernet: __________ MAC → PC2 MAC
IP:       PC1 IP        → PC2 IP
REVEAL FINAL
LAN 1:
Ethernet: PC1 MAC → Router LAN1 MAC
IP:       PC1 IP  → PC2 IP

LAN 2:
Ethernet: Router LAN2 MAC → PC2 MAC
IP:       PC1 IP          → PC2 IP

PACKET TRACER LAB 3

PACKET TRACER: SAME NET → ROUTED

MÅL
Se skillnaden mellan lokal Ethernetkommunikation och kommunikation som kräver routing.
TOPOLOGI
PC1 ── Switch1 ── Router ── Switch2 ── PC2

I Packet Tracer använder ni en router som motsvarighet till routingfunktionen i lektionsmaterialets FortiGate-exempel.

Part A — same network

Börja med PC1 och PC2 i samma IPv4-nät enligt lärarens adressering. Verifiera att de kan kommunicera.

CHALLENGE 1

När två hosts bedömer att de ligger på samma nät: vilken MAC försöker avsändaren få fram med ARP — mottagarens eller routerns?

REVEAL

Mottagarens MAC, eftersom leveransen kan ske direkt på det lokala nätet.

Part B — split the networks

Ändra adresseringen så att PC1 och PC2 ligger på olika subnät. Konfigurera routerinterfaces och default gateway på klienterna.

CHALLENGE 2

Innan ni testar: förutsäg vilken destination-MAC PC1 använder i sin första Ethernet-frame när den skickar ett paket till PC2.

REVEAL

PC1 skickar Ethernet-framen till default gatewayens MAC, inte direkt till PC2:s MAC.

Part C — simulation proof

Skicka ping och följ det i Simulation Mode.

CHALLENGE 3

Dokumentera source/destination MAC före och efter routern. Dokumentera även source/destination IP. Vad förändras?

Part D — break it deliberately

Ta bort eller konfigurera fel default gateway på PC1.

CHALLENGE 4

Vad fungerar fortfarande lokalt? Varför misslyckas trafik till det andra subnätet?

REVEAL

PC1 kan fortfarande kommunicera inom sitt lokala nät om övrig konfiguration är korrekt, men saknar korrekt nästa hopp för destinationer utanför nätet.

Final explanation

FINAL

Förklara skillnaden mellan de två fallen med orden ARP, destination MAC, default gateway och routing.

REVEAL FINAL

På samma nät kan ARP lösa mottagarens IP direkt till mottagarens MAC. På olika nät skickar hosten Ethernet-framen till default gatewayens MAC; routern vidarebefordrar IP-paketet mot det andra nätet och skapar lämplig L2-frame på nästa länk.
