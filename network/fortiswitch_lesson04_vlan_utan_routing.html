BAALSTORM // NÄTVERKSTEKNIK

FYSISKA FORTISWITCHAR · 60–90 MIN · ARBETE I GRUPP

TVÅ SWITCHAR.
TRE VLAN. INGEN ROUTING.

Bygg tre separata lager 2-nät på två FortiSwitchar. Testa hur otaggad datortrafik placeras i rätt VLAN och hur VLAN:en transporteras taggade mellan switcharna.

Mål: skapa VLAN, konfigurera Native VLAN och Allowed VLANs, verifiera kommunikation inom VLAN och förklara varför olika VLAN inte kommunicerar utan routing.

01 // Förbered utrustningen

  • Två fysiska FortiSwitchar, sex datorer och Ethernet-kablar.
  • Administration via konsol eller ett separat, av läraren förberett managementnät.
  • Tre datorer på varje switch: en i varje VLAN. Med fyra datorer gör ni samma tester i två VLAN åt gången och byter sedan till det tredje.
Lärarens startläge: båda switcharna ska vara förberedda i standalone-läge. En FortiLink-hanterad switch konfigureras via FortiGate och följer inte denna instruktion. Byt inte driftläge under labben. Använd endast tilldelade labbportar och en enda länk mellan switcharna. Managementanslutningen får inte skapa en extra väg för labbtrafiken.

Anteckna modell, programversion och befintlig konfiguration. Ta backup enligt lärarens instruktion. Ändra inte managementport, management-VLAN eller switcharnas managementadresser. Kontrollera modellen med get system status.

Exemplen använder port1–port3 för datorer och port8 mellan switcharna. Byt namnen om era tilldelade portar är andra. Kontrollera att port8 faktiskt finns och är ledig.

03 // Förstå FortiSwitchs portinställningar

Inställning Funktion i denna labb
Native VLAN Inkommande otaggad trafik placeras i detta VLAN. Trafik i VLAN:et skickas normalt otaggad ut från porten.
Allowed VLANs Ytterligare VLAN som får passera porten. I labben skickas de taggade. Native VLAN är implicit tillåtet.
Untagged VLANs Kan ange ytterligare VLAN som skickas otaggade ut. Lämna listan utan extra VLAN i denna labb.

En datorport med Native VLAN 10 och inga ytterligare tillåtna VLAN fyller samma funktion som en Cisco-accessport i VLAN 10. Länkporten med Native VLAN 99 och Allowed VLANs 10, 20, 30 fyller samma funktion som en Cisco-trunk med dessa taggade VLAN.

Ett native VLAN per port. Vi använder VLAN 99 som native på switchlänken, så att labbens VLAN 10, 20 och 30 transporteras taggade. VLAN 99 får inga datorer eller IP-adresser.

04 // Konfigurera båda switcharna

Gör samma inställningar på A och B. I standalone-webbgränssnittet finns VLAN och portinställningar vanligtvis under Switch → VLAN och Switch → Interfaces. Menynamn varierar mellan versioner.

  1. Skapa VLAN 10, 20, 30 och 99. Namnge dem gärna PERSONAL, STUDENTER, GASTER och NATIVE.
  2. Konfigurera datorportarna och länkporten enligt tabellen.
  3. Ta bort tidigare extra VLAN från Allowed VLANs och Untagged VLANs på just dessa labbportar.
  4. Spara ändringarna och kontrollera att alla anslutna portar har länk.

CLI-alternativ i standalone-läge

Byt först till era faktiska portnamn. Kör på båda switcharna. Använd GUI om er version har annan syntax. 

config switch vlan
    edit 10
        set description "PERSONAL"
    next
    edit 20
        set description "STUDENTER"
    next
    edit 30
        set description "GASTER"
    next
    edit 99
        set description "NATIVE"
    next
end

config switch interface
    edit "port1"
        set native-vlan 10
        unset allowed-vlans
        unset untagged-vlans
    next
    edit "port2"
        set native-vlan 20
        unset allowed-vlans
        unset untagged-vlans
    next
    edit "port3"
        set native-vlan 30
        unset allowed-vlans
        unset untagged-vlans
    next
    edit "port8"
        set native-vlan 99
        set allowed-vlans 10 20 30
        unset untagged-vlans
    next
end

Skapa ingen länkaggregation. FortiSwitchs CLI-sektion config switch trunk används för trunkgrupper/länkaggregation och behövs inte för denna enda länk som bär flera VLAN.

05 // Verifiera och testa

Kontrollera inställningarna i GUI och med:

show switch vlan
show full-configuration switch interface

Leta efter rätt native-vlan, allowed-vlans och untagged-vlans i varje labbports block. Kontrollera även länkstatus i GUI. Defaultvärden kan utelämnas av vanligt show.

Det sista testet bevisar inte ensamt VLAN-separationen, eftersom datorn också saknar en route till det andra subnätet. Gör nästa test för att skilja IP-adressering från VLAN-tillhörighet.

06 // Samma IP-subnät, olika VLAN

  1. Ändra tillfälligt PC20-B till 172.17.10.22/24. Lämna gateway tom och behåll port2 i VLAN 20.
  2. Från PC10-A: pinga 172.17.10.22. Det ska misslyckas trots att adresserna nu ligger i samma IP-subnät.
  3. Starta Wireshark på PC10-A:s kabelanslutning och använd visningsfiltret arp. Pinga igen. Om ingen ARP-förfrågan visas, töm ARP-cachen för testadressen med operativsystemets verktyg.
  4. Leta efter frågan om vem som har 172.17.10.22. Den skickas som broadcast i VLAN 10 och når inte PC20-B i VLAN 20.
  5. Återställ PC20-B till 172.17.20.12/24 och kontrollera att PC20-A åter kan pinga den.

07 // Följ taggad och otaggad trafik

Datorerna skickar otaggade ramar. Datorportarnas Native VLAN avgör VLAN-tillhörigheten. På länken mellan switcharna skickas VLAN 10, 20 och 30 med 802.1Q-taggar, eftersom länkens Native VLAN är 99. Mottagande switch använder VLAN-ID i taggen och skickar trafiken otaggad till rätt datorport.

Wireshark på datorporten: där ser ni normalt inte switchlänkens taggar. För att observera dem behövs en av läraren förberedd portspegling som bevarar taggar eller en nätverkstapp. Nätverkskort och drivrutiner kan dessutom ta bort taggar före fångsten.

08 // Felsök ett avsiktligt fel

  1. På switch A:s länkport: ändra Allowed VLANs från 10, 20, 30 till 10, 30. Behåll Native VLAN 99.
  2. Testa alla tre A-till-B-förbindelser. Bara VLAN 20 ska sluta fungera.
  3. Jämför inställningarna på båda ändar av länken och identifiera skillnaden.
  4. Återställ Allowed VLANs till 10, 20, 30 och verifiera att alla tre VLAN fungerar.

Om ett test inte ger väntat resultat: kontrollera kabel och länkstatus, datorns IP/mask, lokal brandvägg, datorportens Native VLAN och länkportarnas Allowed VLANs. Kontrollera även att ingen extra otaggad VLAN-lista eller alternativ nätverksanslutning påverkar testet.

09 // Redovisa och återställ

  • Bifoga topologi och portinställningar från båda switcharna.
  • Visa lyckade ping inom alla tre VLAN och det misslyckade testet med samma IP-subnät men olika VLAN.
  • Förklara Native VLAN, Allowed VLANs och skillnaden mot Ciscos access- och trunkinställningar.
  • Förklara vad som skulle behövas för kommunikation mellan VLAN.
  • Återställ datorernas adresser. Läraren avgör om switcharna ska behålla labbkonfigurationen eller återställas från backup. Gör ingen fabriksåterställning.

Svaren sparas inte automatiskt. Kopiera dem till inlämningen eller skriv ut till PDF.

Kontrollera resonemanget efter labben

Varje VLAN är en egen broadcastdomän på lager 2. Native VLAN placerar inkommande otaggad trafik i ett VLAN och skickar det VLAN:ets trafik otaggad ut. Allowed VLANs tillåter labbens övriga VLAN över länken, där de går taggade. En gemensam IP-adressplan slår inte samman olika VLAN. För trafik mellan VLAN behövs routing på lager 3, till exempel i en router, en lager 3-switch eller en brandvägg.
