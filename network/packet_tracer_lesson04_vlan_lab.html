BAALSTORM // NÄTVERKSTEKNIK

PACKET TRACER · 45–60 MIN · ENSKILT ELLER I PAR

VLAN UTAN ROUTING

Skapa tre separata nät på samma switch. Utöka sedan nätet med en andra switch och låt samma VLAN fortsätta över en trunk.

Mål: skapa VLAN, tilldela accessportar, konfigurera en trunk och förklara varför ARP och annan broadcast stannar inom ett VLAN. Ingen router eller lager 3-routing används.

01 // Bygg ett nät med en switch

  1. Starta ett nytt projekt i Packet Tracer.
  2. Lägg in en 2960-switch och sex PC. Döp switchen till S1 och datorerna till PC10-A, PC10-B, PC20-A, PC20-B, PC30-A och PC30-B.
  3. Koppla datorernas FastEthernet0 till switchportarna enligt tabellen. Använd Copper Straight-Through.
  4. På varje PC: öppna Desktop → IP Configuration och välj Static. Alla får masken 255.255.255.0. Lämna gateway och DNS tomma.
PC Port på S1 Planerat VLAN IP-adress /24
PC10-A Fa0/2 10 – Personal 172.17.10.11
PC10-B Fa0/3 10 – Personal 172.17.10.12
PC20-A Fa0/4 20 – Studenter 172.17.20.11
PC20-B Fa0/5 20 – Studenter 172.17.20.12
PC30-A Fa0/6 30 – Gäster 172.17.30.11
PC30-B Fa0/7 30 – Gäster 172.17.30.12

Vänta tills länkarna blivit gröna. Öppna Desktop → Command Prompt på PC10-A och kör ping 172.17.10.12. Upprepa om första försöket misslyckas medan ARP eller portens startläge hanteras.

02 // Skapa tre VLAN och tilldela portar

Öppna S1 → CLI. Tryck Enter vid behov. Svara no om en initial konfigurationsdialog visas. Kör: 

enable
configure terminal
hostname S1
vlan 10
 name PERSONAL
exit
vlan 20
 name STUDENTER
exit
vlan 30
 name GASTER
exit
interface range fastEthernet0/2 - 3
 switchport mode access
 switchport access vlan 10
exit
interface range fastEthernet0/4 - 5
 switchport mode access
 switchport access vlan 20
exit
interface range fastEthernet0/6 - 7
 switchport mode access
 switchport access vlan 30
exit
end
show vlan brief

Kontrollera att rätt portar finns under VLAN 10, 20 och 30. Datorerna skickar vanliga otaggade Ethernetramar. Accessportens inställning avgör vilket VLAN trafiken tillhör.

03 // Testa separationen

Från Ping till Förväntat
PC10-A 172.17.10.12 Fungerar – samma VLAN och subnät
PC20-A 172.17.20.12 Fungerar – samma VLAN och subnät
PC30-A 172.17.30.12 Fungerar – samma VLAN och subnät
PC10-A 172.17.20.12 Misslyckas – annat subnät och ingen gateway
Skilj på VLAN och IP-subnät: det sista testet bevisar inte ensamt VLAN-separation. Datorn saknar också en route till det andra subnätet. Gör därför testet nedan.
  1. Ändra tillfälligt PC20-B:s IP-adress till 172.17.10.22/24. Behåll dess switchport i VLAN 20.
  2. Från PC10-A: kör ping 172.17.10.22. Det ska misslyckas trots att adresserna nu ligger i samma IP-subnät.
  3. Återställ PC20-B till 172.17.20.12/24. Kontrollera att PC20-A åter kan pinga den.

04 // Följ ARP i Simulation Mode

  1. Behåll den ordinarie adressplanen. Byt från Realtime till Simulation.
  2. I Edit Filters: välj ARP och ICMP. Avmarkera övriga protokoll för att göra händelselistan tydligare.
  3. På PC10-A, kör arp -d för att tömma ARP-cachen och sedan ping 172.17.10.12. Om versionen inte stöder cachekommandot, starta om den simulerade datorn och kontrollera adressen före ping.
  4. Använd Capture/Forward för att följa händelserna stegvis.
  5. Öppna ARP-förfrågan och undersök mottagarens MAC-adress. Vilka datorportar skickar S1 förfrågan vidare till?

ARP-förfrågan använder broadcastadressen FF:FF:FF:FF:FF:FF. Den skickas inom VLAN 10, men inte till datorportarna i VLAN 20 eller 30. Efter ARP-svaret kan ICMP-trafiken skickas som unicast.

05 // Utöka med en andra switch

Lägg in en andra 2960 och döp den till S2. Flytta B-datorernas kablar till S2 enligt tabellen. Behåll deras IP-adresser. Koppla sedan S1 Fa0/1 till S2 Fa0/1 med Copper Cross-Over eller automatiskt kabelval.

PC10-A · PC20-A · PC30-A S1: accessportar
S1 ↔ S2 Fa0/1: trunk
PC10-B · PC20-B · PC30-B S2: accessportar
VLAN A-dator på S1 B-dator på S2
10 Fa0/2 Fa0/2
20 Fa0/4 Fa0/4
30 Fa0/6 Fa0/6

På S2: skapa samma VLAN och tilldela datorportarna:

enable
configure terminal
hostname S2
vlan 10
 name PERSONAL
exit
vlan 20
 name STUDENTER
exit
vlan 30
 name GASTER
exit
interface fastEthernet0/2
 switchport mode access
 switchport access vlan 10
exit
interface fastEthernet0/4
 switchport mode access
 switchport access vlan 20
exit
interface fastEthernet0/6
 switchport mode access
 switchport access vlan 30
exit
end

Kör följande på både S1 och S2. VLAN 99 används som native VLAN och får inga datorer eller IP-adresser i denna labb. 

configure terminal
vlan 99
 name NATIVE
exit
interface fastEthernet0/1
 switchport mode trunk
 switchport trunk native vlan 99
 switchport trunk allowed vlan 10,20,30,99
 no shutdown
exit
end
show interfaces trunk
show interfaces fastEthernet0/1 switchport

Kontrollera att länken är operativt i trunk-läge, att native VLAN är 99 i båda ändar och att VLAN 10, 20 och 30 är tillåtna och aktiva. På 2960 behövs inget kommando för att välja trunk-encapsulation.

Upprepa alla tre A-till-B-tester. De ska fungera över switchlänken. Trafiken i VLAN 10, 20 och 30 går nu taggad på trunken och otaggad på datorportarna. Trunken sammanför inte VLAN:en och ger ingen routing mellan dem.

06 // Skapa och hitta ett fel

På S1: ta tillfälligt bort VLAN 20 från trunkens tillåtna lista: 

configure terminal
interface fastEthernet0/1
 switchport trunk allowed vlan 10,30,99
end

Testa alla tre A-till-B-förbindelser. VLAN 20 ska sluta fungera medan VLAN 10 och 30 fungerar. Undersök show interfaces trunk på båda switcharna och återställ: 

configure terminal
interface fastEthernet0/1
 switchport trunk allowed vlan 10,20,30,99
end

07 // Redovisa

  • Spara projektet som vlan_utan_routing.pkt.
  • Bifoga en bild av topologin samt show vlan brief och show interfaces trunk från båda switcharna.
  • Redovisa lyckade ping inom alla tre VLAN och det misslyckade testet med samma IP-subnät men olika VLAN.
  • Förklara skillnaden mellan en accessport och en trunk samt vad som skulle behövas för kommunikation mellan VLAN.

Svaren på sidan sparas inte automatiskt. Kopiera dem till inlämningen eller skriv ut till PDF.

Kontrollera resonemanget efter labben

Varje VLAN är en egen broadcastdomän på lager 2. Accessportar placerar otaggad datortrafik i ett bestämt VLAN. Trunken bär flera VLAN med 802.1Q-taggar; native VLAN 99 är normalt otaggat. Ett VLAN kan därför sträcka sig över flera switchar utan att blandas med andra VLAN. För kommunikation mellan VLAN behövs en lager 3-enhet med rätt gränssnitt, adresser, routing och eventuella tillåtande regler.
