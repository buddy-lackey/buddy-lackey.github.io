NETWORK LAB / 01

ACCESS CONTROL LISTS

Configure a Cisco router to filter traffic between two networks. Build the topology in Packet Tracer, create an ACL and verify how packets are handled.

NETWORK FILTERING LAB ONLINE_

// MISSION

Du ska bygga två nätverk som kommunicerar via en router. När kommunikationen fungerar ska du konfigurera en ACL som blockerar trafik från LAN 1 till LAN 2.

Målet är att förstå hur ACL-regler skapas, var de appliceras och hur du verifierar resultatet.

// NETWORK TOPOLOGY

PC1 192.168.10.10
R1 G0/0 | G0/1
PC2 192.168.20.10
LAN 1
192.168.10.0/24

PC1: 192.168.10.10
Gateway: 192.168.10.1
Router G0/0: 192.168.10.1

LAN 2
192.168.20.0/24

PC2: 192.168.20.10
Gateway: 192.168.20.1
Router G0/1: 192.168.20.1

Använd en router med två Ethernet-interface, exempelvis Cisco 2911. Du kan ansluta datorerna direkt till routern eller använda en switch i varje LAN.

// CHALLENGES

CHALLENGE 01

Build the network

Bygg topologin i Cisco Packet Tracer.

  1. Konfigurera IP-adresser på routerns två interface.
  2. Aktivera interfacen med no shutdown.
  3. Konfigurera IP-adress, nätmask och gateway på PC1 och PC2.
  4. Verifiera att PC1 kan pinga PC2.

Fråga: Varför behövs en router för kommunikationen mellan PC1 och PC2?

Reveal discussion

PC1 och PC2 ligger i olika IP-nätverk. Trafiken måste därför routas via R1. Datorerna använder sina respektive default gateways för att nå det andra nätverket.

CHALLENGE 02

Create a standard ACL

Skapa en standard ACL med nummer 10.

ACL:en ska:

  • Neka trafik med källadress i 192.168.10.0/24.
  • Tillåta övrig trafik.

Fråga: Varför behöver du lägga till en regel som tillåter övrig trafik?

Reveal discussion

Varje traditionell Cisco ACL avslutas logiskt med implicit deny. Utan en tillåtande regel blockeras all trafik som inte matchar en tidigare ACE. 

access-list 10 deny 192.168.10.0 0.0.0.255
access-list 10 permit any
CHALLENGE 03

Apply the ACL

Applicera ACL 10 så att trafik från PC1 mot LAN 2 blockeras.

Fundera innan du konfigurerar:

  • På vilket interface bör ACL:en placeras?
  • Ska den appliceras som in eller out?
  • Vad betyder riktningen i förhållande till routern?
Reveal discussion

En standard ACL matchar bara käll-IP. Därför placeras den traditionellt nära destinationen. 

interface GigabitEthernet0/1
 ip access-group 10 out

Trafik från LAN 1 mot LAN 2 lämnar routern genom G0/1 och kontrolleras av ACL:en.

CHALLENGE 04

Test and verify

Testa från PC1:

ping 192.168.20.10

Kontrollera sedan routern:

show ip access-lists
show ip interface GigabitEthernet0/1

Besvara:

  1. Fungerar ping från PC1 till PC2?
  2. Vilken ACL-regel matchar trafiken?
  3. Vad visar kommandot show ip interface?
  4. Vad händer om ACL:en tas bort från interfacet?
Reveal discussion

Ping från PC1 till PC2 ska blockeras när ACL 10 är korrekt applicerad. Den första ACE:n nekar paket med käll-IP 192.168.10.0/24.

show ip interface kan visa vilken ACL som är applicerad i inkommande respektive utgående riktning.

// COMMAND REFERENCE

Funktion Cisco IOS
Skapa standard ACL access-list 10 deny ...
Tillåt övrig trafik access-list 10 permit any
Applicera inkommande ip access-group 10 in
Applicera utgående ip access-group 10 out
Visa ACL show ip access-lists
Visa interface show ip interface g0/1
Ta bort ACL från interface no ip access-group 10 out
Wildcard: 0.0.0.255 matchar alla adresser inom ett /24-nät när nätadressen anges korrekt. Nollor måste matcha, ettor får variera.

// BONUS CHALLENGE

CHALLENGE 05 / OPTIONAL

Extended ACL

Ta bort standard ACL 10 från interfacet. Skapa sedan en extended ACL som:

  • Nekar ICMP från LAN 1 till LAN 2.
  • Tillåter övrig IP-trafik.

Placera ACL:en inkommande på G0/0. Testa sedan ping igen.

Reveal discussion 
ip access-list extended BLOCK-PING
 deny icmp 192.168.10.0 0.0.0.255 192.168.20.0 0.0.0.255
 permit ip any any
exit

interface GigabitEthernet0/0
 ip access-group BLOCK-PING in

En extended ACL kan matcha både käll- och destinationsadress samt protokoll. Den kan därför placeras närmare källan.

// FINAL QUESTIONS

  1. Vad är skillnaden mellan en ACL och en ACE?
  2. Vad innebär implicit deny?
  3. Varför är ordningen på ACL-regler viktig?
  4. Vad betyder IN och OUT?
  5. Vad är skillnaden mellan standard och extended ACL?
  6. Varför kan stateless ACL:er skapa problem med returtrafik?
Reveal discussion

ACL är hela regellistan, medan ACE är en enskild regel. Regler utvärderas uppifrån och ned och den första matchningen avgör vad som händer.

IN och OUT beskriver paketets riktning i förhållande till interfacet. Traditionella ACL:er håller inte reda på etablerade anslutningar och måste därför konfigureras med hänsyn till trafik i båda riktningarna.
