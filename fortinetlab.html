04 // WHAT DID WE JUST TEST?

CHECKPOINT 5p

Till brandväggen ≠ genom brandväggen

PC-A kan prata med FortiGate. PC-B kan prata med FortiGate.

Betyder det automatiskt att PC-A kan kommunicera med PC-B?

Nej.

Hittills har trafiken haft FortiGate själv som destination.

PC-A → FORTIGATE PC-B → FORTIGATE

Nästa steg är annorlunda:

PC-A → FORTIGATE → PC-B

Nu ska FortiGate vidarebefordra trafik mellan två nät. Då kommer routing och firewall policy in i bilden.

05 // WINDOWS FIREWALL

PREPARE THE ENDPOINTS 5p

Tillåt endast labbens ping

Windows Defender Firewall ska inte stängas av.

I stället skapar vi en specifik regel som tillåter inkommande ICMPv4 Echo Request.

Kör PowerShell som administratör på BÅDE PC-A OCH PC-B.
New-NetFirewallRule -DisplayName "FortiLab ICMPv4" -Direction Inbound -Protocol ICMPv4 -IcmpType 8 -Action Allow

Kontrollera att regeln finns:

Get-NetFirewallRule -DisplayName "FortiLab ICMPv4"

Ni har alltså inte stängt av Windows-brandväggen. Ni har explicit tillåtit exakt den trafik som behövs för labben.

Windows Defender Firewall: ON ICMPv4 Echo Request: ALLOW

10 // PACKET INSPECTION

CHALLENGE 02 10p

Vad måste brandväggen titta på?

PC-A skickar:

SOURCE IP: 192.168.10.10 DESTINATION IP: 192.168.20.10 PROTOCOL: ICMP TYPE: Echo Request

Vilken information behöver FortiGate undersöka för att avgöra om trafiken matchar policyn?

FortiGate kan bland annat använda source och destination IP-adress samt protokoll för att avgöra om trafiken matchar policyn.

Här arbetar vi huvudsakligen med information från nätverkslagret, inte innehållet i någon webbapplikation.

I en senare TCP-labb kan samma princip utökas med TCP/UDP-portar på transportlagret.

11 // STATEFUL OR STATELESS?

CHALLENGE 03 12p

Brandväggen måste förstå trafikflödet

Tänk tillbaka på begreppen stateful och stateless.

PC-A │ │ Echo Request ▼ PC-B PC-A ▲ │ Echo Reply │ PC-B

En stateless packet filter bedömer i princip varje paket utifrån sina regelvillkor utan att hålla reda på en etablerad TCP-session.

En stateful brandvägg håller information om trafikflöden och sessionsstatus där protokollet har sådan state.

VIKTIGT:

ICMP är bra för att demonstrera routing och policyfiltrering, men TCP är bättre för att verkligen studera stateful sessions. TCP har SYN, SYN/ACK, ACK, etablerade sessioner och portar. Det gör skillnaden mellan stateful och stateless tydligare.

Därför använder vi ICMP som introduktion till FortiGate. En senare labb kan använda TCP för session inspection.

12 // WHO BLOCKED IT?

BOSS FIGHT 15p

Felsök trafikflödet

En elev rapporterar:

"Jag kan inte pinga PC-B. FortiGate är trasig."

Inte så snabbt.

Trafiken passerar flera komponenter:

PC-A │ ▼ Windows Defender Firewall │ ▼ Network Interface │ ▼ FortiGate │ ▼ Network Interface │ ▼ Windows Defender Firewall │ ▼ PC-B

Ta fram en metod för att avgöra var trafiken stoppas.

Ni kan exempelvis kontrollera:

Har PC-A rätt IP-adress och nätmask?
Har PC-A rätt default gateway?
Kan PC-A nå sitt FortiGate-interface?
Har PC-B rätt IP och gateway?
Kan PC-B nå sitt FortiGate-interface?
Finns Windows-regeln FortiLab ICMPv4?
Finns rätt FortiGate-policy?
Matchar source/destination rätt nät?
Är policyn ACCEPT eller DENY?

Målet är inte bara att få ping att fungera. Målet är att kunna förklara varför det fungerar eller inte fungerar.
