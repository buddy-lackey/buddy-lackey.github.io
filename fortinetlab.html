01 // INVENTORY

TASK 01 5p

Identifiera din FortiGate

Logga in på brandväggen och dokumentera:

• Hostname

• Firmware-version

• Vilket interface PC-A är ansluten till

• IP-adress på det interfacet

• Vilket interface som ska användas mot PC-B

Innan man skapar regler måste man förstå vilka interfaces och nät trafiken faktiskt passerar.

02 // DEFAULT BEHAVIOUR

TASK 02 6p

Testa innan du skapar en regel

Anslut PC-A och PC-B till varsin sida av FortiGate.

Konfigurera adresser enligt lärarens instruktion eller enligt det nät ni valt.

Testa därefter:

PC-A → ping → PC-B

Fungerar det?

Titta på Firewall Policy. Finns det någon policy som tillåter trafiken?

En brandvägg släpper normalt inte automatiskt trafik mellan interfaces. Det krävs en matchande policy.

Det illustrerar principen "deny unless explicitly allowed".

03 // CREATE YOUR FIRST POLICY

TASK 03 8p

Tillåt trafik från PC-A till PC-B

Skapa en Firewall Policy.

Incoming Interface: PC-A LAN Outgoing Interface: PC-B LAN Source: PC-A network Destination: PC-B network Service: ALL Action: ACCEPT NAT: OFF

Testa sedan:

PC-A → ping → PC-B

Fungerar kommunikationen nu?

04 // STATEFUL FIREWALL

CHALLENGE 01 10p

Vem startade kommunikationen?

Behåll policyn:

PC-A → PC-B → ACCEPT

Skapa INTE motsvarande policy från PC-B till PC-A.

Starta en anslutning från PC-A till en tjänst på PC-B. Det kan exempelvis vara en enkel webbserver om ni har en sådan i labbet.

PC-A → TCP session → PC-B

Studera aktiva sessions i FortiGate medan anslutningen pågår.

Fråga:

Varför kan svarstrafiken från PC-B komma tillbaka även om det inte finns en separat policy som uttryckligen säger: PC-B → PC-A → ACCEPT

FortiGate är stateful.

När PC-A initierar en tillåten anslutning skapar brandväggen information om sessionen.

Returtrafik som hör till samma session kan därför identifieras som legitim returtrafik.

05 // NEW SESSION VS RETURN TRAFFIC

CHALLENGE 02 10p

Testa andra riktningen

Nu ska PC-B försöka initiera en helt ny anslutning till PC-A.

PC-B → NEW CONNECTION → PC-A

Fungerar det?

Jämför detta med returtrafiken i föregående uppgift.

Returtrafiken hörde till en redan etablerad session.

PC-B:s nya anslutning är däremot en ny session och måste själv matcha en policy som tillåter den riktningen.

Detta är en av de tydligaste praktiska demonstrationerna av stateful filtering.

06 // PACKET FILTERING

TASK 06 8p

Från ALL till minsta nödvändiga

Din policy tillåter just nu Service = ALL.

Ändra policyn så att endast exempelvis HTTPS tillåts:

PC-A → PC-B TCP / 443 ACCEPT

Testa sedan:

HTTPS → ska fungera annan TCP-port → ska blockeras

Vad har förändrats säkerhetsmässigt?

Regeln tillåter nu endast det trafikflöde som faktiskt behövs.

Attackytan minskar jämfört med Service = ALL.

07 // RULE ORDER

CHALLENGE 03 10p

Första matchande policy

Skapa eller diskutera följande ordning:

POLICY 1 PC-A → PC-B → HTTPS → DENY POLICY 2 PC-A → PC-B → ALL → ACCEPT

Vad händer med HTTPS?

Flytta därefter ordningen:

POLICY 1 PC-A → PC-B → ALL → ACCEPT POLICY 2 PC-A → PC-B → HTTPS → DENY

Vad händer nu?

Regelordningen är avgörande.

Den första policy som matchar trafikflödet används.

En bred regel ovanför en specifik regel kan därför göra den specifika regeln verkningslös.

08 // OBSERVE SESSIONS

TASK 08 8p

Se brandväggen arbeta

Starta trafik från PC-A till PC-B.

Leta sedan efter aktiva sessions eller motsvarande vy i FortiGate.

Försök identifiera:

• Source IP

• Destination IP

• Source port

• Destination port

• Protocol

• Policy ID

Jämför detta med vad ni tidigare såg i Wireshark.

09 // STATELESS THOUGHT EXPERIMENT

CHALLENGE 04 10p

Hur skulle en stateless brandvägg tänka?

Anta att brandväggen inte hade någon session table.

PC-A:53000 → PC-B:443

PC-B svarar:

PC-B:443 → PC-A:53000

Hur skulle brandväggen veta att paket två hör till anslutningen ovan?

En stateless brandvägg bedömer varje paket separat.

Den måste därför ha regler som även tillåter returtrafiken baserat på adresser, protokoll och portar.

En stateful brandvägg kan istället koppla returpaketet till en redan etablerad session.

10 // BOSS

BOSS FIGHT 15p

Bygg ett minimalt regelverk

Du har följande krav:

PC-A ska kunna nå PC-B på TCP/443.

PC-A ska INTE kunna nå andra portar på PC-B.

PC-B ska INTE få initiera nya anslutningar mot PC-A.

Returtrafik för PC-A:s HTTPS-session ska fungera.

Skapa ett så litet och specifikt policyregelverk som möjligt.

Testa sedan:

PC-A → PC-B:443 EXPECT: PASS PC-A → PC-B:annan port EXPECT: FAIL PC-B → PC-A:new EXPECT: FAIL PC-B → PC-A:return EXPECT: PASS

Förklara varför resultatet visar att FortiGate arbetar stateful.
