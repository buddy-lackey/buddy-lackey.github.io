RTU-17 // HINT SYSTEM

Use only when operational competence is insufficient.

SPOILER WARNING: Varje ledtråd gör uppgiften enklare. Börja alltid med Hint 1.

STAGE 1 // Var börjar jag?

Jag kommer inte förbi login-sidan.

Webbläsaren gör mer än vad du ser på skärmen. Öppna utvecklarverktygen: F12 eller: Ctrl + Shift + I Titta särskilt på fliken: Network Ladda sedan om sidan.

STAGE 2 // Network visar flera filer

Vilken av dem är intressant?

Leta efter filer som beskriver systemets konfiguration. Ett namn som: system.json kan vara intressant. Klicka på requesten och läs svaret.

STAGE 3 // Jag hittade system.json

Titta på objektet: legacyMaintenance Finns det någon funktion som verkar vara avsedd för tekniker eller underhåll? Och finns det en route som webbläsaren kan öppna?

STAGE 4 // Jag har hittat en route

Öppna routen direkt i webbläsaren. Du behöver inte lyckas med den vanliga inloggningen först. Fundera sedan på: Varför får servergränssnittet visa dashboarden trots att du aldrig autentiserades?

STAGE 5 // Jag är inne i RTU:n

Bra. Men uppgiften är inte riktigt färdig.

Undersök gränssnittets olika vyer. En RTU brukar registrera saker som:
  • systemhändelser
  • inloggningar
  • fel
  • underhåll
Finns det en: EVENT LOG ?

STAGE 6 // Event log

Läs loggen noggrant. Några poster handlar om: Legacy field maintenance och: Authentication verification En annan post innehåller det du letar efter.

FULL SOLUTION // Stor spoiler

  1. Öppna RTU-login.
  2. Öppna DevTools med F12.
  3. Välj Network.
  4. Ladda om sidan.
  5. Öppna requesten config/system.json.
  6. Leta efter: legacyMaintenance
  7. Konfigurationen avslöjar: dashboard.html?mode=service
  8. Öppna den routen direkt.
  9. Authentication-kontrollen kringgås och RTU-dashboarden visas.
  10. Öppna EVENT LOG.
  11. Flaggan är: FLAG{legacy_service_bypassed_authentication}
