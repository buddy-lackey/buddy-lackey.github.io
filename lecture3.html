Lecture 03

OSI MODEL, ENCAPSULATION & FIREWALLS

Networks become easier to understand when communication is divided into layers. Each layer has a responsibility, uses information from the layer below, and provides services to the layer above.

// THE OSI MODEL

CHALLENGE 02

Protocol detective

14:02:11  192.168.10.15:51542 → 93.184.216.34:443  TCP
14:02:11  192.168.10.15 → 192.168.10.1  ARP
14:02:12  192.168.10.15 → 8.8.8.8  DNS query
14:02:13  192.168.10.15 → 93.184.216.34  ICMP

Place TCP, ARP, DNS and ICMP at the most appropriate OSI layers.

Bonus: why can mapping real-world protocols perfectly onto the seven-layer OSI model sometimes become messy?

Reveal discussion
TCP → Layer 4.
ARP → commonly associated with Layer 2 / the boundary of 2 and 3.
DNS → Layer 7.
ICMP → Layer 3.

The OSI model is a conceptual model. Real protocol stacks were not necessarily designed to fit perfectly into seven strict boxes.
// ENCAPSULATION
CHALLENGE 03

The packet gets dressed

An application wants to send:

DATA: GET /index.html
APPLICATION DATA
TCP HEADER
APPLICATION DATA
IP HEADER
TCP HEADER
APPLICATION DATA
ETH HEADER
IP HEADER
TCP HEADER
DATA
FCS

Explain what happens as the data travels down the stack.

What happens when the receiving computer performs decapsulation?

Reveal discussion
Each layer adds information needed for its job. TCP adds transport information, IP adds network addressing, and Ethernet adds local-link information and a trailer.

The receiver processes and removes the corresponding information as the data moves back up the stack until the application receives the original application data.
CHALLENGE 04

Which address survives?

A packet travels from a laptop through several routers before reaching a server on another network.

What happens to the Layer 2 source/destination MAC addresses at each routed hop?

What normally happens to the Layer 3 source/destination IP addresses while routing the packet?

Reveal discussion
The Layer 2 frame is replaced for each routed link, so the MAC addresses change from hop to hop.

The IP source and destination normally remain associated with the end hosts while the packet is routed, although technologies such as NAT can modify IP addressing.
// OSI VS TCP/IP
CHALLENGE 05

Seven layers become four

OSI TCP/IP
7 Application Application
6 Presentation
5 Session
4 Transport Transport
3 Network Internet
2 Data Link Network Access / Link
1 Physical

Why do security professionals still talk about OSI layers when real Internet communication is normally described using TCP/IP?

Reveal discussion
OSI provides a useful conceptual vocabulary. Saying "Layer 3 filtering" or "Layer 7 inspection" quickly communicates what information or function is being discussed, even though the Internet itself uses the TCP/IP protocol suite.
// FIREWALLS
CHALLENGE 06

What can the firewall see?

A firewall receives the following packet:
Source MAC    00:11:22:33:44:55
Destination MAC  AA:BB:CC:DD:EE:FF

Source IP     192.168.10.25
Destination IP 203.0.113.50

Protocol      TCP
Source Port   51542
Destination Port 443

Which information belongs to Layer 2, Layer 3 and Layer 4?

Reveal discussion
MAC addresses → Layer 2.
IP addresses → Layer 3.
TCP and port numbers → Layer 4.
CHALLENGE 07

Stateless firewall

Consider this rule:

ALLOW TCP FROM any TO 203.0.113.50 PORT 443

What information does a simple stateless packet filter need to inspect to make this decision?

Does it necessarily know whether this packet belongs to an established connection?

Reveal discussion
It can make the decision from information such as protocol, source/destination IP and source/destination port.

A purely stateless filter evaluates packets individually and does not maintain a connection state table describing previous traffic.
CHALLENGE 08

Stateful firewall

CONNECTION TABLE
------------------------------------------------------------
TCP  10.0.0.25:51542  →  203.0.113.50:443  ESTABLISHED
TCP  10.0.0.31:51891  →  198.51.100.20:22   ESTABLISHED

What additional capability does the state table give the firewall?

Why is this useful for return traffic?

Reveal discussion
A stateful firewall remembers active flows/connections and can relate packets to previous traffic.

For example, when an internal client initiates an allowed connection, the firewall can recognize corresponding return traffic instead of treating every incoming packet as completely unrelated.

Is it correct to say that "a firewall operates at one OSI layer"?

Reveal discussion

HTTP-aware inspection → Layer 7.

Different firewall technologies operate at different layers. Modern firewalls can inspect information from several layers.
CHALLENGE 10

Port 443 does not mean HTTPS

A firewall sees a TCP connection to destination port 443.

Can a Layer 3/4 firewall prove that the application is actually HTTPS simply because the destination port is 443?

Reveal discussion
No. Port 443 is conventionally associated with HTTPS, but a port number alone does not prove which application protocol is actually being carried.

This distinction becomes important when comparing simple packet filtering with application-aware inspection.

CHALLENGE 11

Read the packet

Ethernet II
  Src: 00:16:3e:11:22:33
  Dst: 00:16:3e:aa:bb:cc

Internet Protocol Version 4
  Src: 10.10.10.25
  Dst: 192.0.2.80

Transmission Control Protocol
  Src Port: 49152
  Dst Port: 80

Hypertext Transfer Protocol
  GET /secret.txt HTTP/1.1

Identify the Layer 2, Layer 3, Layer 4 and Layer 7 information.

Bonus: which pieces could a traditional Layer 3/4 firewall use without understanding HTTP?

Reveal discussion
Layer 2 → Ethernet / MAC addresses.
Layer 3 → IPv4 / IP addresses.
Layer 4 → TCP / port numbers.
Layer 7 → HTTP / GET request.

A traditional Layer 3/4 firewall can primarily make decisions using IP addresses, protocol and port information without parsing the HTTP request itself.
