BAALSTORM // FIREWALL LAB PARROT OS + UFW
$ sudo ufw status verbose

HOST FIREWALL.

I den här labben arbetar ni två och två. En Parrot-dator blir server och skyddas av UFW. Den andra Parrot-datorn blir klient och försöker ansluta.

Målet är att se skillnaden mellan en tjänst som körs och en tjänst som faktiskt är tillgänglig genom brandväggen.

LABBMILJÖ

Arbeta endast mot datorn i din egen grupp.
Använd inte portskanning eller tester mot andra enheter på skolans nätverk.

00 // TOPOLOGY

SKOLANS WIFI │ ┌─────────┴─────────┐ │ │ WINDOWS LAPTOP A WINDOWS LAPTOP B │ │ VMware VMware │ │ Bridged mode Bridged mode │ │ PARROT A PARROT B SERVER CLIENT + UFW

När VMware använder Bridged försöker Parrot få en egen IP-adress från samma nätverk som Windows-datorn använder.

Detta fungerar bara om skolans nät tillåter VM:er och direkt kommunikation mellan klienter. Om det inte fungerar behöver läraren använda ett separat labbnät.

01 // SET VMWARE TO BRIDGED

BASIC 5p

Kontrollera nätverksläget

Stäng av Parrot-VM:n om det behövs och öppna dess inställningar i VMware.

VM Settings ↓ Network Adapter ↓ Bridged

Starta sedan Parrot.

02 // FIND YOUR IP

BASIC 10p

Kör:

ip -4 addr

Visa routing:

ip route
PARROT A IP: _______________________

PARROT B IP: _______________________

DEFAULT GATEWAY: ___________________

Ni behöver känna till båda Parrot-maskinernas IP-adresser.

03 // TEST CONNECTIVITY

BASIC 10p

Från Parrot A, testa Parrot B:

ping -c 3 <PARROT-B-IP>

Exempel:

ping -c 3 192.168.1.52

Gör sedan motsvarande från B till A.

A → B fungerar: YES / NO

B → A fungerar: YES / NO
Om båda datorerna har internet men inte kan nå varandra kan skolans Wi-Fi använda client isolation. Säg då till läraren istället för att fortsätta felsöka UFW.

04 // WHO IS SERVER?

ROLE ASSIGNMENT 5p
PARROT A = SERVER + UFW PARROT B = CLIENT

Parrot A ska alltså köra tjänsten. Parrot B ska försöka ansluta till den.

05 // CREATE A WEB SERVICE

SERVER 10p

På Parrot A:

mkdir -p ~/ufw-lab cd ~/ufw-lab

Skapa en enkel webbsida:

echo "BAALSTORM UFW LAB - ACCESS GRANTED" > index.html

Starta en webbserver på TCP/8000:

python3 -m http.server 8000

Terminalen bör visa något liknande:

Serving HTTP on 0.0.0.0 port 8000 ...
Låt terminalen vara öppen. Servern kör så länge processen körs.

06 // IS THE PORT REALLY OPEN?

INTERMEDIATE 10p

Öppna en ny terminal på Parrot A.

ss -tln | grep 8000

Ni bör se att TCP/8000 lyssnar.

LISTEN ... 0.0.0.0:8000

Programmet väntar på inkommande TCP-anslutningar till port 8000.

Det betyder dock inte automatiskt att andra datorer får ansluta. En brandvägg kan fortfarande blockera trafiken.

07 // TEST FROM CLIENT

CLIENT 10p

På Parrot B:

curl http://<PARROT-A-IP>:8000

Exempel:

curl http://192.168.1.51:8000

Förväntat resultat:

BAALSTORM UFW LAB - ACCESS GRANTED

Ni kan även öppna samma adress i webbläsaren.

08 // CHECK UFW

FIREWALL 10p

På Parrot A:

sudo ufw status verbose

Om UFW är avstängd kan ni få:

Status: inactive

09 // DEFAULT POLICY

INTERMEDIATE 15p

På Parrot A:

sudo ufw default deny incoming sudo ufw default allow outgoing

Aktivera sedan UFW:

sudo ufw enable

Kontrollera:

sudo ufw status verbose

Ni bör se ungefär:

Default: deny (incoming) allow (outgoing)

Nya inkommande anslutningar blockeras som standard.

Utgående trafik tillåts som standard.

10 // TEST AGAIN

OBSERVE 10p

På Parrot B:

curl http://<PARROT-A-IP>:8000

Fungerar anslutningen fortfarande?

RESULTAT: __________________________

På Parrot A, kontrollera samtidigt:

ss -tln | grep 8000
Det viktiga här är att servern fortfarande kör och fortfarande lyssnar. Om klienten inte kommer fram är det brandväggen som stoppar trafiken.

11 // ALLOW TCP/8000

INTERMEDIATE 15p

På Parrot A:

sudo ufw allow 8000/tcp

Kontrollera:

sudo ufw status numbered

Testa sedan igen från Parrot B:

curl http://<PARROT-A-IP>:8000

Förväntat:

BAALSTORM UFW LAB - ACCESS GRANTED

12 // SERVICE VS FIREWALL

CONCEPT 15p
SERVICE RUNNING + FIREWALL DENY = CONNECTION FAILS SERVICE RUNNING + FIREWALL ALLOW = CONNECTION WORKS

Förklara med egna ord skillnaden mellan att en port lyssnar och att porten är åtkomlig från nätverket.

13 // REMOVE THE RULE

FIREWALL 10p

Visa regler med nummer:

sudo ufw status numbered

Ta bort regeln direkt med syntaxen:

sudo ufw delete allow 8000/tcp

Kontrollera igen:

sudo ufw status numbered

Testa från klienten igen.

14 // LEAST PRIVILEGE

CHALLENGE 20p

Den tidigare regeln släppte in alla som kunde nå Parrot A.

ALLOW 8000/tcp

Nu ska ni istället bara tillåta Parrot B.

På Parrot A:

sudo ufw allow from <PARROT-B-IP> to any port 8000 proto tcp

Exempel:

sudo ufw allow from 192.168.1.52 to any port 8000 proto tcp

Kontrollera:

sudo ufw status numbered
SOURCE: _______________________

DESTINATION PORT: _____________

PROTOCOL: _____________________

Least privilege.

Vi tillåter endast den klient som faktiskt behöver tillgång, istället för att öppna tjänsten för alla.

15 // STATEFUL FIREWALL

CONCEPT 20p

När B ansluter till A sker ungefär:

PARROT B PARROT A 49152 -----------------------> 8000 TCP connection 49152 <----------------------- 8000 response traffic

Vi skapade bara en regel som tillät anslutningen till TCP/8000 på A.

Varför behöver vi normalt inte skapa en separat regel för varje svarspaket tillbaka till B?

UFW bygger på Linux brandväggsfunktioner som håller reda på anslutningens tillstånd.

Svarstrafik som hör till en redan tillåten anslutning kan därför identifieras som en del av samma session.

Detta är stateful filtering.

16 // BONUS: NETCAT

BONUS 15p

En enklare TCP-tjänst

Python-servern använder HTTP. Netcat kan istället användas för att demonstrera en enklare rå TCP-anslutning.

På Parrot A kan ni testa:

nc -l 9000

På Parrot B:

nc <PARROT-A-IP> 9000

Skriv text i den ena terminalen och se den visas i den andra.

Det här är bonus. Python-servern på TCP/8000 är huvudövningen eftersom HTTP är enklare att se och testa.

17 // BOSS

BOSS 30p

FIREWALL TROUBLESHOOTING

INCIDENT: PARROT A IP: 192.168.50.21 PARROT B IP: 192.168.50.22 Server: python3 -m http.server 8000 Parrot A: ss shows TCP/8000 LISTENING Parrot B: curl http://192.168.50.21:8000 FAILS UFW: Status active Default: deny incoming allow outgoing

Besvara:

1. Kör servern fortfarande?

2. Vilket kommando kan bevisa det?

3. Vad är den mest sannolika orsaken till att B inte kommer fram?

4. Skapa en regel där endast B får komma åt TCP/8000.

5. Hur verifierar du att regeln finns?

6. Hur testar du från B?
På A: ss -tln | grep 8000 sudo ufw allow from 192.168.50.22 to any port 8000 proto tcp sudo ufw status numbered På B: curl http://192.168.50.21:8000

Om servern lyssnar men anslutningen blockeras är brandväggen en rimlig sak att undersöka.

18 // CLEANUP

END OF LAB

Stoppa Python-servern med:

CTRL + C

På Parrot A kan ni återställa UFW-reglerna för labben.

Visa först reglerna:

sudo ufw status numbered

Ta bort de regler ni skapade under övningen.

Exempel:

sudo ufw delete allow 8000/tcp

Om ni skapade en IP-specifik regel kan samma regel anges efter delete:

sudo ufw delete allow from <PARROT-B-IP> to any port 8000 proto tcp

Ta bort labbkatalogen:

rm -r ~/ufw-lab
Stäng inte av eller återställ UFW generellt om läraren inte säger till. Ta endast bort de regler som skapades för labben.
